<h2 id="script-사용"><code>&#x3C;script></code> 사용<a class="anchor after" aria-hidden="true" tabindex="-1" href="#script-사용"><span class="anchor-icon">#</span></a></h2>
<p><code>async</code>와 <code>defer</code> 모두 사용하지 않는 기본 모드입니다.</p>
<p><code>&#x3C;script></code>는 인라인 코드인 경우 파싱 되고 실행되지만 외부 스크립트인 경우 리소스를 다운로드하고, 파싱 되고, 실행됩니다. 브라우저는 스크립트 파일을 다운로드하고 파싱 되고 실행될 때까지 HTML 파싱을 중단합니다.</p>

<p><code>async</code> 속성은 브라우저에게 스크립트 리소스 다운이 완료되면 파싱을 중단하고 스크립트 파일을 실행하라고 알려주는 역할을 합니다.</p>
<h3 id="렌더링-순서-1">렌더링 순서<a class="anchor after" aria-hidden="true" tabindex="-1" href="#렌더링-순서-1"><span class="anchor-icon">#</span></a></h3>

<h2 id="script--defer-사용"><code>&#x3C;script ... defer></code> 사용<a class="anchor after" aria-hidden="true" tabindex="-1" href="#script--defer-사용"><span class="anchor-icon">#</span></a></h2>
<p><code>defer</code> 속성은 브라우저에게 HTML 파싱이 완료되면 스크립트 파일을 실행하라고 알려주는 역할을 합니다.</p>

<h3 id="특징-1">특징<a class="anchor after" aria-hidden="true" tabindex="-1" href="#특징-1"><span class="anchor-icon">#</span></a></h3>
<p><code>async</code> 속성과 <code>defer</code> 속성의 렌더링 동작을 비교해 살펴보도록 하겠습니다.</p>
<h4 id="async와-공통점"><code>async</code>와 공통점<a class="anchor after" aria-hidden="true" tabindex="-1" href="#async와-공통점"><span class="anchor-icon">#</span></a></h4>
<p><code>async</code>와 <code>defer</code> 모두 스크립트 리소스를 다운로드하는 동안에 파싱이 중단되지 않습니다.</p>
<h4 id="async와-차이점"><code>async</code>와 차이점<a class="anchor after" aria-hidden="true" tabindex="-1" href="#async와-차이점"><span class="anchor-icon">#</span></a></h4>
<p><code>async</code>와 <code>defer</code>는 2가지 차이점이 있습니다.</p>
<ol>
<li><code>async</code>는 스크립트 리소스 다운로드가 완료된 시점에 스크립트가 실행되지만, <code>defer</code>는 HTML 파싱 하는 동안에 스크립트 리소스를 다운로드하고 HTML 파싱이 완료되면 스크립트가 실행됩니다.</li>
<li><code>async</code>(default 값인 <code>async=true</code>일 경우)는 다운로드가 완료된 시점에 스크립트가 실행되어 스크립트 실행 순서를 보장할 수 없지만, <code>defer</code>의 경우 정의된 순서대로 스크립트가 실행됩니다.</li>
</ol>
<h3 id="지원-브라우저-1">지원 브라우저<a class="anchor after" aria-hidden="true" tabindex="-1" href="#지원-브라우저-1"><span class="anchor-icon">#</span></a></h3>

<h2 id="무엇을-사용할-것인가">무엇을 사용할 것인가<a class="anchor after" aria-hidden="true" tabindex="-1" href="#무엇을-사용할-것인가"><span class="anchor-icon">#</span></a></h2>
<p>브라우저는 기본적으로 <code>&#x3C;script></code> 태그를 만나면 파싱을 중단하고 스크립트를 다운, 파싱, 실행 과정을 진행합니다. <code>&#x3C;body></code> 태그가 닫히기 바로 직전에 <code>&#x3C;script></code> 태그를 선언하었다면, 이미 거의 모든 HTML 파싱이 종료된 상태이기 때문에, <code>async</code> 속성을 사용하든 <code>defer</code> 속성을 사용하든 크게 의미가 없게 됩니다.</p>
<p>이번에는 <code>&#x3C;scirpt></code>가 <code>&#x3C;body></code> 태그가 닫히기 바로 직전에 선언되지 않아 <code>async</code> 혹은 <code>defer</code> 속성을 사용해야 할 때, 어떤 속성을 사용하는 것이 좋은지 살펴보도록 하겠습니다.</p>
<h3 id="async를-사용해야-할-때"><code>async</code>를 사용해야 할 때<a class="anchor after" aria-hidden="true" tabindex="-1" href="#async를-사용해야-할-때"><span class="anchor-icon">#</span></a></h3>
<p>스크립트 파일에 종속성이 없는 경우 <code>async</code> 속성을 사용하는 것이 좋습니다.</p>
<p><code>async</code>는 스크립트 리소스 다운로드가 완료되면 파싱을 중단하고 스크립트가 실행되기 때문에, 어느 시점에 HTML 파싱이 중단될지 보장할 수 없습니다. DOM에 종속성이 없어서  HTML 파싱 중 어느 시점에 스크립트가 실행되든지 상관없을 경우 <code>async</code> 속성을 사용하는 것이 좋습니다.</p>
<p><code>async</code>(<code>async=true</code>인 경우)는 스크립트 리소스 다운로드가 완료된 순서대로 스크립트가 실행되기 때문에, 여러 스크립트가 정의된 경우 어느 스크립트가 먼저 실행될지 보장할 수 없습니다. 스크립트 파일 간에 종속성이 없어서 어떤 순서로 스크립트가 실행돼도 상관없을 경우 <code>async</code> 속성을 사용하는 것이 좋습니다.</p>
<h3 id="defer를-사용해야-할-때"><code>defer</code>를 사용해야 할 때<a class="anchor after" aria-hidden="true" tabindex="-1" href="#defer를-사용해야-할-때"><span class="anchor-icon">#</span></a></h3>
<p><code>async</code>과 반대로 종속성이 있는 경우 <code>defer</code> 속성을 사용하는 것이 좋습니다.</p>
<p>DOM과 종속성이 있어서, DOM이 전부 생성되어야 정상적인 동작을 할 수 있는 경우 <code>defer</code> 속성을 사용하는 것이 좋습니다.</p>
<p>스크립트 간에 종속성이 있어서, 스크립트 실행 순서가 항상 <code>&#x3C;script></code> 정의 순서로 실행되어야 하는 경우 <code>defer</code> 속성을 사용하는 것이 좋습니다.</p>
<h2 id="부록">부록<a class="anchor after" aria-hidden="true" tabindex="-1" href="#부록"><span class="anchor-icon">#</span></a></h2>
<h3 id="defer-async를-동시-사용하면"><code>defer</code>, <code>async</code>를 동시 사용하면?<a class="anchor after" aria-hidden="true" tabindex="-1" href="#defer-async를-동시-사용하면"><span class="anchor-icon">#</span></a></h3>
<p><code>async</code>와 <code>defer</code> 속성이 모두 지정된 경우 <code>async</code> 속성을 지원하는 최신 브라우저는 기본적으로 <code>async</code> 속성을 따라갑니다. 하지만 <code>async</code> 속성을 지원하지 않는 구형 브라우저는 <code>defer</code> 속성의 지원 여부에 따라 결정됩니다. <code>defer</code> 속성을 지원하는 경우 <code>defer</code> 속성에 의해 비동기적으로 스크립트를 실행하지만 <code>defer</code> 조자 지원하지 않는 브라우저의 경우에는 동기적으로 스크립트를 실행합니다.</p>
<h3 id="noscript"><code>&#x3C;noscript></code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#noscript"><span class="anchor-icon">#</span></a></h3>
<p>자바스크립트 실행이 비활성화되어 있거나 자바스크립트 기능이 없는 구형 브라우저(최신 브라우저는 자바스크립트를 지원하지 않는 경우를 찾아볼 수 없습니다)의 경우 <code>&#x3C;noscript></code> 태그 내의 HTML이 파싱 되어 화면에 그려집니다.</p>
