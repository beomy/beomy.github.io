<h2 id="쿠키란">쿠키란<a class="anchor after" aria-hidden="true" tabindex="-1" href="#쿠키란"><span class="anchor-icon">#</span></a></h2>
<p>쿠키는 HTTP 쿠키, 웹 쿠키 또는 브라우저 쿠키라고 불리웁니다. 쿠키는 서버가 사용자의 웹 브라우저에 전송하는 작은 데이터 조각입니다. 브라우저는 이 데이터 조각을 저장해 놓았다가 동일한 서버에 재 요청 시 이 정보를 함께 전송합니다.</p>
<p>서버에서 쿠키를 설정해 주기 때문에 쿠키가 브라우저 간에 공유된다고 혼동을 줄 수 있지만, 브라우저에서 쿠키를 저장하기 때문에 브라우저 간의 쿠키는 공유 되지 않습니다.</p>
<p>쿠키가 클라이언트 측에 정보를 저장할 수 있는 유일한 방법이 였을 때에는 클라이언트 측에 정보를 저장하기 위해 쿠키가 주로 사용되었지만, 모든 요청 마다 쿠키가 함께 전송되기 때문에 성능 저하의 원인이 될 수 있어 지금은 클라이언트 측에 데이터를 저장하기 위해서 로컬 스토리지나 세션 스토리지를 사용하는 것이 좋습니다.</p>
<h2 id="쿠키-목적">쿠키 목적<a class="anchor after" aria-hidden="true" tabindex="-1" href="#쿠키-목적"><span class="anchor-icon">#</span></a></h2>
<p>쿠키는 상태가 없는(stateless) HTTP 프로토콜에서 상태 정보를 기억하기 위해 사용됩니다. 상태가 없는(무 상태) 프로토콜은 이전 요청과 상관없이 각각의 요청을 독립적인 트랜잭션으로 취급하기 때문에 이전 요청의 상태를 저장하지 않습니다. 쿠키를 사용하면 이전 요청의 상태를 저장할 수 있기 때문에 쿠키는 크게 아래와 같은 3가지 목적으로 사용됩니다.</p>
<ul>
<li>세션 관리(Session Management): 서버에 저장해야 할 로그인, 장바구니 등의 정보 관리</li>
<li>개인화(Personalization): 사용자 선호, 테마 등의 정보 관리</li>
<li>트레킹(Tracking): 사용자 행동을 기록하고 분석하기 위한 정보 관리</li>
</ul>
<h2 id="쿠키-구조">쿠키 구조<a class="anchor after" aria-hidden="true" tabindex="-1" href="#쿠키-구조"><span class="anchor-icon">#</span></a></h2>
<p>쿠키의 구조는 아래와 같이 3개의 요소로 구성됩니다.</p>
<ul>
<li>이름</li>
<li>값</li>
<li>속성(이름/값의 쌍)</li>
</ul>
<p>이름과 값은 필수 값입니다. 속성은 옵션 값으로 쿠키 만료 기간, 도메인 등의 정보가 올 수 있습니다.</p>
<h2 id="쿠키-전송">쿠키 전송<a class="anchor after" aria-hidden="true" tabindex="-1" href="#쿠키-전송"><span class="anchor-icon">#</span></a></h2>
<p>서버는 HTTP 요청에 응답 할 때 응답에 <code>Set-Cookie</code> 헤더를 전송하면, 브라우저에서는 <code>Set-Cookie</code> 헤더를 보고 쿠키를 저장합니다. 그 후 브라우저에서 같은 서버에 요청을 할 때 <code>Cookie</code> 헤더에 쿠키를 포함하여 전송합니다.</p>
<h3 id="서버---브라우저">서버 -> 브라우저<a class="anchor after" aria-hidden="true" tabindex="-1" href="#서버---브라우저"><span class="anchor-icon">#</span></a></h3>
<p>서버에서 설정한 쿠키를 브라우저로 전달하기 위해 응답 헤더 중 <code>Set-Cookie</code> 헤더에 쿠키를 추가하여 응답을 보내면 됩니다.</p>
<h4 id="set-cookie-헤더"><code>Set-Cookie</code> 헤더<a class="anchor after" aria-hidden="true" tabindex="-1" href="#set-cookie-헤더"><span class="anchor-icon">#</span></a></h4>
<p>서버에서 브라우저로 보내는 응답 헤더에 <code>Set-Cookie</code> 헤더를 포함하면 브라우저가 쿠키를 저장하게 됩니다. <code>Set-Cookie</code> 헤더를 설정할 수 있는 간단한 형태는 아래 코드와 같습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> &#x3C;cookie-name>=&#x3C;cookie-value></span></span></code></pre>

<h3 id="브라우저---서버">브라우저 -> 서버<a class="anchor after" aria-hidden="true" tabindex="-1" href="#브라우저---서버"><span class="anchor-icon">#</span></a></h3>
<p>브라우저에서 서버로 보내는 요청 헤더 주에 <code>Cookie</code>라는 헤더에 서버로 보낼 쿠키들이 저장되어 있습니다. 별도로 <code>Cookie</code> 헤더를 설정해 줄 필요 없이 유효한 쿠키가 있다면 자동으로 <code>Cookie</code> 헤더에 유효한 쿠키들이 추가되어 서버로 요청을 보내게 됩니다.</p>
<h4 id="cookie-헤더"><code>Cookie</code> 헤더<a class="anchor after" aria-hidden="true" tabindex="-1" href="#cookie-헤더"><span class="anchor-icon">#</span></a></h4>
<p>브라우저는 <code>Cookie</code> 헤더에 서버에서 전달 받은 모든 쿠키들을 담아 서버에 요청을 보냅니다. 아래 코드와 같이 <code>Cookie</code> 헤더에 쿠키를 포함하여 서버에 요청을 보냅니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">GET</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> /sample_page.html </span><span style="color:#A0111F;--shiki-dark:#FF9492">HTTP</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">/</span><span style="color:#023B95;--shiki-dark:#91CBFF">1.1</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Host</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> beomy.github.io</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; post=cookie</span></span></code></pre>
<p>서버에서 <code>Set-Cookie</code> 헤더로 id와 post 쿠키를 전달 받은 이후에 브라우저에서 서버로 새로운 요청을 보낼 때 <code>Cookie</code> 헤더에 위의 코드와 같이 id와 post 쿠키를 함께 전달합니다.</p>
<h2 id="쿠키-속성">쿠키 속성<a class="anchor after" aria-hidden="true" tabindex="-1" href="#쿠키-속성"><span class="anchor-icon">#</span></a></h2>
<p>서버에서 쿠키를 전송할 때 만료일, 지속 시간, 도메인, 경로 속성 등을 추가해서 전송할 수 있습니다. 만료된 쿠키는 서버로 다시 전송되지 않습니다. 도메인과 경로 속성이 정의 되었다면, 특정 도메인과 경로에만 쿠키를 전송할 수 있도록 제한할 수 있습니다.</p>
<h3 id="라이프-타임-속성">라이프 타임 속성<a class="anchor after" aria-hidden="true" tabindex="-1" href="#라이프-타임-속성"><span class="anchor-icon">#</span></a></h3>
<p>쿠키가 유지되는 시간을 지정할 수 있는 속성으로 <code>Expires</code>와 <code>Max-Age</code> 두가지가 있습니다.</p>
<h4 id="expires"><code>Expires</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#expires"><span class="anchor-icon">#</span></a></h4>
<p><code>Expires</code> 속성을 사용하면 속성에 정의된 날짜에 삭제되는 쿠키를 만듭니다. 사용 방법은 아래 코드와 같습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; Expires=Sun, 29 Aug 2021 12:00:00 GMT;</span></span></code></pre>
<h4 id="max-age"><code>Max-Age</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#max-age"><span class="anchor-icon">#</span></a></h4>
<p><code>Max-Age</code> 속성을 사용하면 속성에 정의된 기간 이후에 삭제되는 쿠키를 만듭니다. 사용 방법은 아래 코드와 같습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; Max-Age=600;</span></span></code></pre>
<p><code>Max-Age</code> 속성은 초 단위를 사용합니다. 위의 코드는 10분 동안 유지되는 쿠키입니다. 음수가 지정되면 해당 쿠키는 즉시 만료됩니다. <code>Expires</code>와 <code>Max-Age</code> 속성 둘 다 지정되었을 경우 <code>Max-Age</code> 속성을 더 우선합니다.</p>
<h4 id="세션-쿠키">세션 쿠키<a class="anchor after" aria-hidden="true" tabindex="-1" href="#세션-쿠키"><span class="anchor-icon">#</span></a></h4>
<p><code>Expires</code>와 <code>Max-Age</code> 두가지 속성이 정의되지 않는 쿠키를 세션 쿠키라고 합니다. 세션 쿠키는 현재 브라우저의 세션이 끝날 때 삭제되는 쿠키입니다. 크롬 브라우저에서 크롬을 종료한 후에도 세션 쿠키가 남아 있는 이슈가 있는데, 백그라운드에서 동작하고 있는 크롬 프로세스를 모두 종료해야 세션 쿠키가 삭제됩니다.</p>
<p><img src="/assets/img/posts/browser/close-chrome.png" alt="크롬 종료" loading="lazy" decoding="async" width="260" height="232" srcset="/assets/img/posts/browser/nextImageExportOptimizer/close-chrome-opt-640.WEBP 640w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<p>MAC OS에서는 크롬 브라우저를 닫아도 완전히 종료된 것이 아니기 때문에, 위의 그림에서 종료 버튼을 클릭하여 완전히 종료해 주어야 합니다.</p>
<h3 id="보안-속성">보안 속성<a class="anchor after" aria-hidden="true" tabindex="-1" href="#보안-속성"><span class="anchor-icon">#</span></a></h3>
<p>브라우저에서 서버로 보내는 요청에는 자동으로 쿠키가 함께 포함되어 전송되기 때문에 쿠키를 사용하면 보안에 취약해 질 수 있습니다. 보안 취약점을 보완하기 위해 사용되는 속성으로 <code>Secure</code>와 <code>HttpOnly</code>, <code>SameSite</code> 세 가지가 있습니다.</p>
<h4 id="secure"><code>Secure</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#secure"><span class="anchor-icon">#</span></a></h4>
<p><code>Secure</code> 속성이 정의 된 쿠키는 HTTPS 요청일 경우에만 쿠키를 전송합니다. <code>Secure</code> 속성을 사용했더라도 민감한 정보는 쿠키에 담지 않는 것이 좋습니다. 사용 방법은 아래 코드와 같습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; Secure;</span></span></code></pre>
<h4 id="httponly"><code>HttpOnly</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#httponly"><span class="anchor-icon">#</span></a></h4>
<p><a href="/tech/etc/xss-xsrf/#xsscross-site-scripting">XSS</a> 공격을 방어하기 위해 <code>HttpOnly</code> 속성이 정의 된 쿠키는 자바스크립트의 <code>document.cookie</code> API를 통해 접근할 수 없습니다. <code>HttpOnly</code> 쿠키는 서버에 전송하는 용도로만 사용할 수 있습니다. 사용 방법은 아래 코드와 같습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; HttpOnly;</span></span></code></pre>
<p>아래 그림은 <code>HttpOnly</code> 속성이 정의 된 쿠키와 정의 되지 않은 쿠키의 <code>document.cookie</code>를 비교한 그림입니다.</p>
<p><img src="/assets/img/posts/browser/httponly-cookie.gif" alt="document.cookie 비교" loading="lazy" decoding="async" width="674" height="640" srcset="/assets/img/posts/browser/nextImageExportOptimizer/httponly-cookie-opt-640.WEBP 640w, /assets/img/posts/browser/nextImageExportOptimizer/httponly-cookie-opt-1080.WEBP 1080w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<h4 id="samesite"><code>SameSite</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#samesite"><span class="anchor-icon">#</span></a></h4>
<p><a href="/tech/etc/xss-xsrf/#xsrfcrose-site-request-forgery">XSRF</a> 공격을 방어하기 위해 <code>SameSite</code> 속성을 사용할 수 있습니다. <code>SameSite</code> 속성은 <code>None</code>, <code>Lax</code>, <code>Static</code> 중 하나를 설정할 수 있습니다.</p>
<ul>
<li><code>None</code>: <code>SameSite</code> 속성이 등장하기 전에 동작하던 쿠키 방식입니다. <code>None</code>으로 설정된 쿠키는 크로스 사이트 요청에도 항상 전송됩니다. 즉 A 사이트에서 설정된 쿠키가 B 사이트에서 발생하는 요청에도 쿠키가 전달됩니다.</li>
<li><code>Lax</code>: 웹 페이지 이동과 안전한 HTTP 메서드 요청의 경우 쿠키를 전송합니다. <code>&#x3C;a href></code>, <code>&#x3C;link href> </code>, <code>&#x3C;form method=get></code>에서는 쿠키가 전송됩니다.</li>
<li><code>Static</code>: <code>Strict</code>로 설정된 쿠키는 <code>Lax</code>에서 허용한 몇 가지 예외를 포함하여 모든 크로스 사이트 요청에 쿠키를 전송하지 않습니다.</li>
</ul>
<p>사용 방법은 아래 코드와 같습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; SameSite=Lax;</span></span></code></pre>
<h3 id="스코프-속성">스코프 속성<a class="anchor after" aria-hidden="true" tabindex="-1" href="#스코프-속성"><span class="anchor-icon">#</span></a></h3>
<p><code>Domain</code>과 <code>Path</code> 두 가지 속성을 사용하면 쿠키의 유효 범위를 설정할 수 있습니다.</p>
<h4 id="domain"><code>Domain</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#domain"><span class="anchor-icon">#</span></a></h4>
<p><code>Domain</code> 속성에는 쿠키가 전송되게 될 호스트가 정의됩니다. <code>Domain</code> 속성에 정의 된 URL에 쿠키가 전송됩니다. 사용 방법은 아래 코드와 같습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; Domain=beomy.io;</span></span></code></pre>
<p>위의 코드의 <code>Domain=beomy.io</code>와 같이 <code>Domain</code>이 정의되면 쿠키들은 <code>sub.beomy.io</code>, <code>domain.beomy.io</code>와 같은 서브 도메인에서도 쿠키가 포함되어 전송됩니다.</p>
<p><code>Domain</code>이 정의 되어 있지 않으면 현재 서버 주소가 기본 값으로 설정되며, <code>Domain</code>을 정의한 쿠키와 달리 서브 도메인은 포함되지 않습니다.</p>
<h4 id="path"><code>Path</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#path"><span class="anchor-icon">#</span></a></h4>
<p><code>Domain</code> 속성은 쿠키의 도메인의 유효 범위를 지정한다면, <code>Path</code> 속성은 쿠키의 디렉토리의 유효 범위를 지정합니다. 사용 방법은 아래 코드와 같습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; Path=/cookie;</span></span></code></pre>
<p>위의 코드처럼 <code>Path=/cookie</code>로 <code>Path</code> 속성을 지정하면 <code>/cookie</code>, <code>/cookie/path</code>, <code>/cookie/domain</code>와 같은 서브 디렉토리에서 쿠키가 포함되어 전송됩니다.</p>
<h2 id="부록">부록<a class="anchor after" aria-hidden="true" tabindex="-1" href="#부록"><span class="anchor-icon">#</span></a></h2>
<h3 id="samesite-속성"><code>SameSite</code> 속성<a class="anchor after" aria-hidden="true" tabindex="-1" href="#samesite-속성"><span class="anchor-icon">#</span></a></h3>
<p><code>SameSite</code> 속성은 <a href="/tech/browser/cookie/#%ED%8D%BC%EC%8A%A4%ED%8A%B8-%ED%8C%8C%ED%8B%B0-%EC%BF%A0%ED%82%A4%EC%99%80-%EC%84%9C%EB%93%9C-%ED%8C%8C%ED%8B%B0-%EC%BF%A0%ED%82%A4">서드 파티 쿠키</a>의 보안 이슈를 해결하기 위해 만들어진 속성으로, Cross-Site 요청에 쿠키를 포함할지 포함하지 않을지 결정하는 쿠키 보안 속성입니다.</p>
<h4 id="same-site-란">Same Site 란<a class="anchor after" aria-hidden="true" tabindex="-1" href="#same-site-란"><span class="anchor-icon">#</span></a></h4>
<p><a href="https://publicsuffix.org/list/public_suffix_list.dat">공개 접미사 목록</a>을 보면 어떤 사이트들이 같은 사이트로 판단되는지 알 수 있습니다. 예를 들어, <code>www.naver.com</code>과 <code>search.naver.com</code>는 같은 사이트로 판단되지만, 공개 접미사 목록에 있는 <code>github.io</code>는 <code>beomy.github.io</code>와 <code>samesite.github.io</code>는 서로 다른 사이트로 판단합니다.</p>
<h4 id="domain-속성과-samesite-속성의-차이"><code>Domain</code> 속성과 <code>SameSite</code> 속성의 차이<a class="anchor after" aria-hidden="true" tabindex="-1" href="#domain-속성과-samesite-속성의-차이"><span class="anchor-icon">#</span></a></h4>
<p><code>Domain</code> 속성과 <code>SameSite</code> 속성의 차이를 이해하기 위해서는 도메인과 사이트의 정의를 구분하여 이해하는 것이 도움이 됩니다. <a href="https://www.hostwinds.kr/tutorials/whats-difference-domain-web-site">hostwinds</a>에 아래 그림과 같이 도메인과 사이트의 차이를 한눈에 이해 할 수 있는 그림이 있습니다. 도메인이 집 주소라면 사이트는 그 집 주소 위에 지어진 집으로 이해할 수 있습니다.</p>
<p><img src="/assets/img/posts/browser/domain_site_diff.jpeg" alt="도메인과 사이트의 차이" loading="lazy" decoding="async" width="541" height="343" srcset="/assets/img/posts/browser/nextImageExportOptimizer/domain_site_diff-opt-640.WEBP 640w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<p><code>Domain</code> 속성은 설정된 집 주소에 쿠키를 전달하도록 하는 속성이라면 <code>SameSite</code>는 내 집에서만 쿠키를 전달 받을지 선택하는 속성입니다. 예를 들어 아래 코드와 같이 설정된 쿠키가 있다면,</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; Domain=beomy.github.io; SameSite=None; Secure</span></span></code></pre>
<p>위의 코드는 <code>beomy.github.io</code>로 쿠키를 전달하겠다는 의미입니다. 반면에 아래 코드와 같이 설정된 쿠키는,</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="http"><code><span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">Set-Cookie</span><span style="color:#A0111F;--shiki-dark:#FF9492">:</span><span style="color:#032563;--shiki-dark:#ADDCFF"> id=beomy; SameSite=Strict;</span></span></code></pre>
<p>위의 코드는 같은 사이트가 아니면 쿠키를 전달하지 않겠다는 의미입니다.</p>
<h4 id="samesite-속성과-secure-속성의-종속성"><code>SameSite</code> 속성과 <code>Secure</code> 속성의 종속성<a class="anchor after" aria-hidden="true" tabindex="-1" href="#samesite-속성과-secure-속성의-종속성"><span class="anchor-icon">#</span></a></h4>
<p><code>Secure</code> 속성은 HTTPS 요청에만 쿠키를 전송하기 위해 사용되는 속성이지만, <code>SameSite</code> 속성을 <code>None</code>으로 설정할 때 보안 취약점을 보완하기 위해 <code>Secure</code> 속성이 함께 정의되어야 합니다. 아래 코드와 같이 사용되어야 <code>SameSite=None</code>과 <code>Secure</code> 속성이 함께 사용되어야 합니다.</p>

<h3 id="퍼스트-파티-쿠키와-서드-파티-쿠키">퍼스트 파티 쿠키와 서드 파티 쿠키<a class="anchor after" aria-hidden="true" tabindex="-1" href="#퍼스트-파티-쿠키와-서드-파티-쿠키"><span class="anchor-icon">#</span></a></h3>
<p>쿠키는 <code>Domain</code> 속성을 정의할 수 있는데 <code>Domain</code> 속성의 값이 현재 보고 있는 페이지의 도메인과 동일하면 퍼스트 파티 쿠키, 도메인이 다르다면 서드 파티 쿠키라고 이야기합니다.</p>
<h4 id="퍼스트-파티-쿠키-first-party-cookie">퍼스트 파티 쿠키 (First-Party Cookie)<a class="anchor after" aria-hidden="true" tabindex="-1" href="#퍼스트-파티-쿠키-first-party-cookie"><span class="anchor-icon">#</span></a></h4>
<p>퍼스트 파티 쿠키는 사용자가 방문한 웹 사이트에서 직접 발행한 쿠키를 말합니다. 예를 들어 사용자가 <code>naver.com</code>에 접속했을 때, <code>naver.com</code>에서 로그인 인증 쿠키를 발행하는 경우는 퍼스트 파티 쿠키에 해당됩니다.</p>
<h4 id="서드-파트-쿠키-third-party-cookie">서드 파트 쿠키 (Third-Party Cookie)<a class="anchor after" aria-hidden="true" tabindex="-1" href="#서드-파트-쿠키-third-party-cookie"><span class="anchor-icon">#</span></a></h4>
<p>서드 파티 쿠키는 사용자가 방문한 웹 사이트에서 발행한 쿠키가 아니라, 다른 웹 사이트에서 발행한 쿠키를 말합니다. 구글은 2023년 말까지 크롬에서 서드 파티 쿠키 지원을 중단하겠다고 발표했습니다.</p>
<p>보통 광고 서버에서 발행하는 쿠키가 서드 파티 쿠키입니다. 예를 들어 사용자가 <code>ads.com</code>의 스크립트가 심어져 있는 <code>amazon.com</code>에서 A 상품을 보았다면, <code>ads.com</code>은 사용자가 <code>amazon.com</code>에서 A 상품을 봤다는 정보를 담아 쿠키를 발행합니다. 그리고 사용자가 <code>beomy.github.io</code>라는 사이트에 방문 했을 때, <code>beomy.github.io</code>에 <code>ads.com</code> 스크립트가 심어져 있다면 <code>ads.com</code>은 사용자가 <code>amazon.com</code>에서 A 상품을 봤다는 것을 쿠키를 통해 알 수 있기 때문에 쿠키 정보로 광고를 보여줄 수 있게 됩니다.</p>
<h3 id="브라우저-저장소">브라우저 저장소<a class="anchor after" aria-hidden="true" tabindex="-1" href="#브라우저-저장소"><span class="anchor-icon">#</span></a></h3>
<p>브라우저에서 지원하는 저장소는 쿠키 이외에 로컬 스토리지(localStorage)와 세션 스토리지(sessionStorage)가 있습니다. 로컬 스토리지와 세션 스토리지는 모두 HTML5에 추가된 key-value 스토리지입니다.</p>
<h4 id="로컬-스토리지">로컬 스토리지<a class="anchor after" aria-hidden="true" tabindex="-1" href="#로컬-스토리지"><span class="anchor-icon">#</span></a></h4>
<p>로컬 스토리지는 데이터를 인위적으로 지우기 전까지 계속 저장되기 때문에 사용자 개인정보 등 민감한 정보를 로컬 스토리지에 저장하는 것은 피해야 합니다. 로컬 스토리지는 <code>window.localStorage</code>에 저장되고, 도메인 마다 각각의 로컬 스토리지가 존재합니다.</p>
<p>로컬 스토리지의 메서드는 <code>setItem(key, value)</code>, <code>getItem(key)</code>, <code>removeItem(key)</code>, <code>clear()</code> 이렇게 4가지 종류가 있습니다.</p>
<ul>
<li><code>setItem(key, value)</code>: <code>key</code> 값을 key로 하여 <code>value</code>를 저장합니다.</li>
<li><code>getItem(key)</code>: <code>key</code> 값으로 저장된 value를 가져옵니다.</li>
<li><code>removeItem(key)</code>: <code>key</code> 값으로 저장된 데이터를 삭제합니다.</li>
<li><code>clear()</code>: 전체 로컬 스토리지를 삭제합니다.</li>
</ul>
<p>로컬 스토리지는 key-value 형태로 데이터가 저장되는데, key와 value 모두 문자열 형태로 저장됩니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="js"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">localStorage.</span><span style="color:#622CBC;--shiki-dark:#DBB7FF">setItem</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="color:#032563;--shiki-dark:#ADDCFF">'number'</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">, </span><span style="color:#023B95;--shiki-dark:#91CBFF">1234</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">);</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">localStorage.</span><span style="color:#622CBC;--shiki-dark:#DBB7FF">getItem</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="color:#032563;--shiki-dark:#ADDCFF">'number'</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">) </span><span style="color:#66707B;--shiki-dark:#BDC4CC">// '1234'</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">localStorage.</span><span style="color:#622CBC;--shiki-dark:#DBB7FF">setItem</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="color:#032563;--shiki-dark:#ADDCFF">'object'</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">, {});</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">localStorage.</span><span style="color:#622CBC;--shiki-dark:#DBB7FF">getItem</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(</span><span style="color:#032563;--shiki-dark:#ADDCFF">'object'</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">) </span><span style="color:#66707B;--shiki-dark:#BDC4CC">// '[object Object]'</span></span></code></pre>
<p>로컬 스토리지에 저장될 때 <code>toString</code> 메서드가 호출된 형태로 저장됩니다. 객체를 그대로 로컬 스토리지에 저장할 경우 <code>toString</code> 메서드가 호출된 형태인 <code>[object 생성자]</code> 형태로 저장되기 때문에, 객체를 로컬 스토리지에 저장해야 할 경우 <code>JSON.stringify</code>를 사용하여 저장되어야 합니다.</p>
<h4 id="세션-스토리지">세션 스토리지<a class="anchor after" aria-hidden="true" tabindex="-1" href="#세션-스토리지"><span class="anchor-icon">#</span></a></h4>
<p>세션 스토리지는 세션 종료 시(브라우저를 닫을 경우) 데이터가 삭제됩니다. 세션 스토리지는 <code>window.sessionStorage</code>에 저장됩니다. 로컬 스토리지와 마찬가지로 도메인 마다 각각의 세션 스토리지가 존재합니다. 로컬 스토리지와 동일하게, <code>setItem(key, value)</code>, <code>getItem(key)</code>, <code>removeItem(key)</code>, <code>clear()</code> 이렇게 4가지 종류의 메서드가 있습니다. 세션 스토리지도 key-value 형태로 데이터가 저장되며, key와 value 모두 문자열 형태로 저장되기 때문에, 로컬 스토리지와 동일하게 객체를 저장해야 할 경우 <code>JSON.stringify</code>를 사용하여 저장되어야 합니다.</p>
