18:T1975e,<p><code>package.json</code>에는 프로젝트에 대한 설명, 종속성 패키지, 실행 스크립트 등의 정보를 담는 매니페이스(Manifest) 파일입니다. 이번 포스트에서는 <code>package.json</code>에서 설정할 수 있는 필드 값들을 하나씩 살펴보도록 하겠습니다.</p>
<p>사용하는 패키지 매니저(NPM, Yarn, PNPM 과 같은)에 따라 설정 가능한 필드들이 다를 수 있기 때문에 사용하는 패키지 매니저의 공식 홈페이지(<a href="https://docs.npmjs.com/cli/v8/configuring-npm/package-json">NPM</a>, <a href="https://yarnpkg.com/configuration/manifest">Yarn 2+</a>, <a href="https://pnpm.io/package_json">PNPM</a>)에서 설정 가능한 필드를 확인하는 것이 좋습니다.</p>
<p>eslint나 prettier 등의 라이브러리 설정(eslint의 경우 <code>eslintConfig</code> 필드)도 <code>package.json</code>에서 가능하기 때문에 이러한 설정 역시 사용하는 라이브러리의 공식 홈페이지에서 확인하고 사용하는 것이 좋습니다.</p>
<p><code>package.json</code>에 설정 가능한 필드를 하나씩 살펴보도록 하겠습니다. 필드 이름 옆 괄호로 어떠한 환경에서 설정 가능한 필드인지 나타내었습니다.</p>
<h2 id="name"><code>name</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#name"><span class="anchor-icon">#</span></a></h2>
<p><code>name</code> 필드는 프로젝트의 이름을 나타냅니다. 아래와 같이 <code>name</code> 필드를 작성할 수 있습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="json"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">{</span></span>

<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre>
<p><code>@beomy/</code>처럼 <code>name</code> 필드는 <code>@</code>로 시작하여 스코프를 지정할 수도 있습니다.</p>
<h2 id="version"><code>version</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#version"><span class="anchor-icon">#</span></a></h2>
<p><code>version</code> 필드는 프로젝트의 버전을 나타냅니다. 아래와 같이 <code>version</code> 필드를 작성할 수 있습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="json"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">{</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">  "version"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#032563;--shiki-dark:#ADDCFF">"1.2.3"</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre>
<blockquote>
<p><strong>NPM 패키지에서 <code>name</code>과 <code>version</code></strong></p>
<p>프로젝트가 NPM에 배포(Publish) 될 때 <code>name</code>와 <code>version</code> 필드는 필수 값입니다. <code>name</code>와 <code>version</code> 필드는 NPM 패키지의 식별자이기 때문에 <code>name</code>와 <code>version</code> 필드를 합친 값(예를 들어, <code>@beomy/blog@1.2.3</code>)은 유니크 한 값이여야 합니다.</p>
</blockquote>
<blockquote>
<p><strong>오픈소스의 버전 구분</strong></p>
<p>버전은 아래 그림과 같이 Major, Minor, Patch로 구성되어 있습니다. 이런 형태의 버전 표시방법은 오픈소스 프로젝트에 일반적으로 사용됩니다.</p>
<p><img src="/assets/img/posts/etc/package_version.png" alt="package.json version" loading="lazy" decoding="async" width="410" height="191" srcset="/assets/img/posts/etc/nextImageExportOptimizer/package_version-opt-640.WEBP 640w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<ul>
<li>Major: API가 변경/삭제 되어 사용자가 Major 버전을 업데이트 할 경우 기존의 코드가 동작하지 않을 수 있을 때, Major 버전을 업데이트하여 배포합니다.</li>
<li>Minor: 이전 버전과 호환되는 방식으로 API가 추가/변경 되었을 때 Minor 버전을 업데이트하여 배포합니다.</li>
<li>Patch: 이전 버전과 호환되는 버그 수정을 할 경우 Patch 버전을 업데이트하여 배포합니다.</li>
</ul>
</blockquote>

<h2 id="dependencies"><code>dependencies</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#dependencies"><span class="anchor-icon">#</span></a></h2>

<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="json"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">{</span></span>

<p>NPM을 사용할 경우 <code>npm install &#x3C;종속 패키지 이름></code>, Yarn을 사용할 경우 <code>yarn add &#x3C;종속 패키지 이름></code>, PNPM을 사용할 경우 <code>pnpm install &#x3C;종속 패키지 이름></code> 명령어를 사용하면 패키지를 설치하고 <code>dependencies</code> 필드에 설치 된 종속 패키지가 버전 정보와 함께 저장됩니다.</p>
<blockquote>
<p><strong>패키지 버전 표시 방법</strong></p>
<p>패키지에 종속 패키지를 추가할 경우 <code>dependencies</code> 필드에 <code>&#x3C;패키지 이름>: "&#x3C;패키지 버전 정보>"</code> 형태로 저장됩니다. 패키지를 설치할 때 <code>&#x3C;패키지 버전 정보></code>와 매칭되는 패키지가 설치됩니다. <code>&#x3C;패키지 버전 정보></code>의 형태는 아래와 같습니다.</p>
<ul>
<li><code>version</code>: 정확한 <code>version</code>의 패키지와 매칭됩니다.</li>
<li><code>1.2.x</code>: <code>1.2.0</code>, <code>1.2.1</code>와 같이 <code>1.2</code> 버전 대역의 패키지와 매칭됩니다.</li>
<li><code>>version</code>: <code>version</code>보다 큰 버전의 패키지와 매칭됩니다.</li>
<li><code>>=version</code>: <code>version</code>보다 크거나 같은 버전의 패키지와 매칭됩니다.</li>
<li><code>&#x3C;version</code>: <code>version</code>보다 작은 버전의 패키지와 매칭됩니다.</li>
<li><code>&#x3C;=version</code>: <code>version</code>보다 작거나 같은 버전의 패키지와 매칭됩니다.</li>
<li><code>~version</code>: <code>version</code>과 가장 동일한 버전의 패키지와 매칭됩니다. 예를 들어,
<ul>
<li><code>~1.2.3</code>은 <code>>=1.2.3 &#x3C;1.3.0-0</code>과 동일한 의미입니다.</li>
<li><code>~1.2</code>는 <code>>=1.2.0 &#x3C;1.3.0-0</code>과 <code>1.2.x</code>와 동일한 의미입니다.</li>
<li><code>~1</code>은 <code>>=1.0.0 &#x3C;2.0.0-0</code>과 <code>1.x</code>와 동일한 의미입니다.</li>
</ul>
</li>
<li><code>^version</code>: <code>version</code>과 호환 가능한 버전의 패키지와 매칭됩니다. 예를 들어,
<ul>
<li><code>^1.2.3</code>은 <code>>=1.2.3 &#x3C;2.0.0-0</code>과 동일한 의미입니다.</li>
<li><code>^0.2.3</code>은 <code>>=0.2.3 &#x3C;0.3.0-0</code>과 동일한 의미입니다.</li>
<li><code>^0.0.3</code>은 <code>>=0.0.3 &#x3C;0.0.4-0</code>과 동일한 의미입니다.</li>
</ul>
</li>
<li><code>*</code>: 모든 버전의 패키지와 매칭됩니다.</li>
<li><code>""</code>(공백 문자): <code>*</code>와 동일합니다.</li>
<li><code>version1 - version2</code>: <code>>=version1 &#x3C;=version2</code>와 동일합니다.</li>
<li><code>range1 || range2</code>: <code>range1</code> 또는 <code>range2</code>에 만족하는 버전의 패키지와 매칭됩니다.</li>
<li><code>path/path/path</code>: <code>path/path/path</code> 로컬 경로에 해당하는 패키지와 매칭됩니다.</li>
</ul>
</blockquote>

<h2 id="peerdependencies"><code>peerDependencies</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#peerdependencies"><span class="anchor-icon">#</span></a></h2>
<p><code>peerDependencies</code> 종속성은 상속 받아야 하는 종속성을 나열하는 필드입니다. 아래와 같이 사용할 수 있습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="json"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">{</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">  "peerDependencies"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: {</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">    "react"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#032563;--shiki-dark:#ADDCFF">"*"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">,</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">    "react-dom"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#032563;--shiki-dark:#ADDCFF">"*"</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  }</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre>
<p>상속 받아야 하는 종속성이란 패키지 개발에 필요한 종속성을 peer(해석하면 또래)에게 제공받는 종속성입니다.</p>
<p>예를 들어 react와 emotion을 사용하여 UI 컴포넌트를 패키지로 만든다고 하면, react나 emotion은 UI 컴포넌트 패키지 입장에서는 패키지 사용자에게서 제공받아야 합니다. 별도의 react와 emotion을 사용하면 사용자와 생성자가 각각의 react, emotion을 가지고 있기 때문에 react, emotion 패키지 내부의 데이터(예를 들면 emotion의 테마 정보)를 공유해 사용할 수 없게 됩니다.</p>
<h2 id="bundledependencies-npm"><code>bundleDependencies</code> (NPM)<a class="anchor after" aria-hidden="true" tabindex="-1" href="#bundledependencies-npm"><span class="anchor-icon">#</span></a></h2>
<p><code>bundleDependencies</code> 필드는 <code>bundledDependencies</code> 이름으로 사용될 수 있습니다. <code>bundleDependencies</code> 이름 그대로 패키지를 배포(publish) 할 때 번들로 제공할 패키지를 배열로 정의합니다. 아래와 같이 사용할 수 있습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="json"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">{</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">  "bundleDependencies"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: [</span></span>
<span class="line"><span style="color:#032563;--shiki-dark:#ADDCFF">    "renderized"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">,</span></span>

<h2 id="optionaldependencies"><code>optionalDependencies</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#optionaldependencies"><span class="anchor-icon">#</span></a></h2>
<p><code>optionalDependencies</code> 필드는 이름 그대로 선택적 종속성 패키지를 나열하는 필드입니다. 종속성이 사용되지만 패키지를 찾을 수 없거나 설치에 실패한 경우에도 패키지 설치를 계속 진행하기 위해 사용하는 필드 입니다. 아래와 같이 사용할 수 있습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="json"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">{</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">  "optionalDependencies"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: {</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">    "fsevents"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#032563;--shiki-dark:#ADDCFF">"^5.0.0"</span></span>

<h2 id="dependenciesmeta-yarn-2-pnpm"><code>dependenciesMeta</code> (Yarn 2+, PNPM)<a class="anchor after" aria-hidden="true" tabindex="-1" href="#dependenciesmeta-yarn-2-pnpm"><span class="anchor-icon">#</span></a></h2>
<p><code>dependenciesMeta</code> 필드는 <code>dependencies</code> 필드와 <code>devDependencies</code> 필드에 나열된 패키지들의 추가 설정을 할 수 있는 필드입니다. 프로젝트가 모노레포로 구성되어 여러 개의 workspace가 있는 경우 프로젝트 루트의 <code>package.json</code>에 정의되어야 합니다. 아래와 같이 사용할 수 있습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="json"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">{</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">  "dependenciesMeta"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: {</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">    "fsevents"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: {</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">      "built"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#023B95;--shiki-dark:#91CBFF">false</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">,</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">      "optional"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#023B95;--shiki-dark:#91CBFF">false</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">,</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">      "unplugged"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#023B95;--shiki-dark:#91CBFF">false</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">    }</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  }</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre>
<p>설정 할 패키지 이름을 키로 하고 값으로 오는 객체에 Yarn 2+에서는 <code>build</code>, <code>optional</code>, <code>unplugged</code>, PNPM에는 <code>injected</code> 설정을 추가할 수 있습니다. 각각의 설정의 내용은 아래와 같습니다.</p>
<ul>
<li><code>built</code>(Yarn 2+): 빌드 스크립트를 실행할지 실행하지 않을지 결정하는 플래그입니다. <code>false</code>를 지정하면 빌드 스크립트를 실행하지 않습니다. <code>.yarnrc.yml</code> 파일에 <code>enableScripts: false</code>를 저장하면 모든 패키지의 빌드 스크립트를 실행하지 않게 됩니다.</li>
<li><code>optional</code>(Yarn 2+): 단어 그대로 옵셔널을 설정 할 수 있는 플래그입니다. <code>true</code>를 지정하면 설치가 성공한 것으로 판단되어 <code>os</code>, <code>cpu</code>, <code>libc</code> 등의 패키지 제약을 설정하는 필드들을 무시하게 됩니다. 이 옵션이 <code>true</code>로 설정된 패키지는 패키지가 컴파일 될 때 <code>optionalDependencies</code> 필드에 작성되어 집니다.</li>
<li><code>unplugged</code>(Yarn 2+): 자바스크립트가 아닌 다른 언어로 된 스크립트를 포함하는 패키지에만 필요한 설정입니다. <code>true</code>인 경우 설치 시 패키지가 <code>.yarn/unplugged</code> 디렉토리(<code>.yarnrc.yml</code> 설정에서 디렉토리 이름 변경 가능)로 분리되어 설치됩니다.</li>
<li><code>injected</code>(PNPM): <code>true</code>로 설정하면 패키지가 심볼릭 링크가 아닌 하드 링크됩니다.</li>
</ul>

<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="json"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">{</span></span>

<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">    "react-dom"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: {</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">      "optional"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#023B95;--shiki-dark:#91CBFF">true</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">    }</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  }</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre>
<p>패키지의 optional을 설정할 수 있는데, <code>optional</code> 값을 <code>true</code>로 설정할 경우 패키지 사용자쪽에서 <code>peerDependencies</code>로 패키지를 추가하지 않아도 에러가 발생하지 않게 됩니다.</p>

<p>Yarn 2+에서는 <code>bin</code>, <code>browser</code>, <code>main</code>, <code>module</code>, <code>exports</code> 필드를 오버라이드 할 수 있고, <code>access</code>, <code>executableFiles</code>, <code>registry</code> 필드를 추가로 설정할 수 있습니다.</p>
<ul>
<li><code>access</code>: NPM에 패키지를 공개할지 공개하지 않을지 결정하는 필드입니다. <code>public</code>, <code>restricted</code> 두 개의 값 중 하나를 설정해야 하는데, <code>restricted</code>을 설정하면 패키지가 비공개 됩니다.</li>
<li><code>executableFiles</code>: 기본적으로 <code>bin</code> 필드에 나열된 파일 외에는 실행 가능한 파일로 표시되지 않습니다. <code>executableFiles</code> 필드를 사용하면 <code>bin</code> 필드를 통해 직접 실행할 수 없는 파일의 경우에도 실행가능 플래그(파일 권한 r(read), w(write), x(execute) 중 x)가 설정됩니다.</li>
<li><code>registry</code>: 패키지의 레지스토리 경로를 저장하는 필드입니다.</li>
</ul>
<p>PNPM에서는 <code>bin</code>, <code>main</code>, <code>exports</code>, <code>types</code>(또는 <code>typings</code>), <code>module</code>, <code>browser</code>, <code>cpu</code>, <code>os</code> 필드 등을 오버라이드 할 수 있고, <code>executableFiles</code>, <code>directory</code>, <code>linkDirectory</code> 필드를 추가로 설정할 수 있습니다.</p>
<ul>
<li><code>executableFiles</code>: Yarn 2+와 동일한 기능을 하는 필드입니다.</li>
<li><code>directory</code>: 현재 <code>package.json</code> 위치를 기준으로 배포(publish) 되는 디렉토리를 저장하는 필드입니다.</li>
<li><code>linkDirectory</code>: <code>true</code>로 설정할 경우 개발 중에 <code>publishConfig.directory</code> 위치에 심볼릭 링크가 생성됩니다.</li>
</ul>

<h2 id="directories"><code>directories</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#directories"><span class="anchor-icon">#</span></a></h2>
<p>CommonJS 패키지 스펙에서는 <code>directories</code> 필드를 사용하여 패키지 구성을 나타낼 수 있습니다. 아래와 같이 사용할 수 있습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="json"><code><span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">{</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">  "directories"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: {</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">    "bin"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#032563;--shiki-dark:#ADDCFF">"./bin"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">,</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">    "doc"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#032563;--shiki-dark:#ADDCFF">"./doc"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">,</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">    "lib"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#032563;--shiki-dark:#ADDCFF">"./lib"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">,</span></span>
<span class="line"><span style="color:#024C1A;--shiki-dark:#72F088">    "man"</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">: </span><span style="color:#032563;--shiki-dark:#ADDCFF">"./man"</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  }</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre>
<ul>
<li><code>directories.bin</code>: <code>bin</code> 필드와 동일한 기능을 하는 필드입니다. <code>directories.bin</code>와 <code>bin</code> 하나의 필드만 설정되어야 합니다.</li>
<li><code>directories.doc</code>: 패키지의 문서, 마크다운 파일들의 위치를 표시하는 필드입니다.</li>
<li><code>directories.lib</code>: 패키지의 라이브러리의 위치를 표시하는 필드입니다.</li>
<li><code>directories.man</code>: <code>man</code> 필드와 동일한 기능을 하는 필드입니다. 매뉴얼 페이지의 경로를 저장합니다. <code>man</code> 필드에 배열 형태로 저장하는 것을 간단(Sugar)하게 만들 수 있게 제공되는 필드입니다.</li>
</ul>
<p><a href="https://github.com/npm/cli/blob/latest/package.json">npm-cli</a>에서 <code>directories</code> 필드가 설정되어 있는 것을 확인할 수 있습니다.</p>
