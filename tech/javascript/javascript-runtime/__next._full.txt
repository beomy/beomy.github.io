<h2 id="싱글-스레드-논-블로킹-언어-javascript">싱글 스레드, 논-블로킹 언어: JavaScript<a class="anchor after" aria-hidden="true" tabindex="-1" href="#싱글-스레드-논-블로킹-언어-javascript"><span class="anchor-icon">#</span></a></h2>
<p>자바스크립트는 싱글 스레드, 논-블로킹 언어입니다. 자바스크립트에서 싱글 스레드는 무엇을 의미하는지, 논-블로킹은 무엇인지 알아보도록 하겠습니다.</p>
<h3 id="싱글-스레드">싱글 스레드<a class="anchor after" aria-hidden="true" tabindex="-1" href="#싱글-스레드"><span class="anchor-icon">#</span></a></h3>
<p>싱글 스레드는 하나의 힙 영역과 하나의 콜 스택을 가집니다. 하나의 콜 스택을 가진다는 의미는 한 번에 한 가지 일 밖에 하지 못한다는 의미입니다. 예를 들어 네트워크 요청을 한다면, 응답이 올 때까지 다른 일은 하지 못하고 마냥 기다릴 수밖에 없습니다.</p>
<h3 id="콜-스택">콜 스택<a class="anchor after" aria-hidden="true" tabindex="-1" href="#콜-스택"><span class="anchor-icon">#</span></a></h3>
<p><a href="https://ko.wikipedia.org/wiki/%EC%BD%9C_%EC%8A%A4%ED%83%9D">콜 스택</a>은 함수가 실행되는 순서를 기억하고 있습니다. 함수를 실행하려면 스택의 가장 위에 해당 함수를 넣게 되고, 함수에서 리턴이 일어나면 스택의 가장 위쪽에서 함수를 꺼냅니다. 간단한 코드 예제를 살펴보도록 하겠습니다.</p>

<h3 id="논-블로킹">논-블로킹<a class="anchor after" aria-hidden="true" tabindex="-1" href="#논-블로킹"><span class="anchor-icon">#</span></a></h3>
<p>싱글 스레드는 스택이 하나밖에 없기 때문에, 한 번에 한 가지 일 밖에 할 수 없습니다. 예를 들어 네트워크 요청을 한다면 응답이 올 때까지 다른 일은 하지 못하고 마냥 기다릴 수밖에 없습니다.</p>
<h4 id="블로킹">블로킹<a class="anchor after" aria-hidden="true" tabindex="-1" href="#블로킹"><span class="anchor-icon">#</span></a></h4>
<p>이것이 왜 문제가 되느냐? 웹 브라우저에서 코드가 실행되는데, 코드가 종료될 때까지 유저가 클릭을 해도 어떠한 반응을 하지 않는 상태가 됩니다. 사용자에게 원활한 UI를 제공해야 한다면, 콜 스택이 멈추게 해서는 안 됩니다. 콜 스택이 멈춘 상태를 블로킹 상태라고 합니다.</p>
<p><img src="/assets/img/posts/javascript/blocking.gif" alt="블로킹" loading="lazy" decoding="async" width="1088" height="710" srcset="/assets/img/posts/javascript/nextImageExportOptimizer/blocking-opt-640.WEBP 640w, /assets/img/posts/javascript/nextImageExportOptimizer/blocking-opt-1080.WEBP 1080w, /assets/img/posts/javascript/nextImageExportOptimizer/blocking-opt-1920.WEBP 1920w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<p>ajax는 실제로는 비동기로 동작하지만, 이해를 위해 동기적으로 동작한다 가정한 예제입니다. 위의 그림과 같이 블로킹이 되면 사용자 화면의 버튼을 클릭해도 반응이 없는, 사용자와 인터랙션(interaction) 할 수 없는 상태가 됩니다.</p>
<p><img src="/assets/img/posts/javascript/blocking.png" alt="블로킹" loading="lazy" decoding="async" width="566" height="298" srcset="/assets/img/posts/javascript/nextImageExportOptimizer/blocking-opt-640.WEBP 640w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<p>위의 그림과 같은 경고 메시지를 보신 적이 있다면, 사용자 인터랙션이 없는 블로킹 상태를 보셨다는 것입니다. 블로킹 상태를 해결하는 방법은 논-블로킹, 비동기 콜백을 사용하는 것입니다.</p>
<h4 id="논-블로킹-1">논-블로킹<a class="anchor after" aria-hidden="true" tabindex="-1" href="#논-블로킹-1"><span class="anchor-icon">#</span></a></h4>

<h2 id="자바스크립트-런타임">자바스크립트 런타임<a class="anchor after" aria-hidden="true" tabindex="-1" href="#자바스크립트-런타임"><span class="anchor-icon">#</span></a></h2>
<p>싱글 스레드인 자바스크립트가 매번 5초가 지났는지 체크하지 않고, 5초 후에 콜백을 호출할 수 있는 이유는 브라우저가 자바스크립트를 실행하는 것 이상의 의미를 가지기 때문입니다.</p>
<p><img src="/assets/img/posts/javascript/javascript_runtime.png" alt="자바스크립트 런타임" loading="lazy" decoding="async" width="1294" height="904" srcset="/assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime-opt-640.WEBP 640w, /assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime-opt-1080.WEBP 1080w, /assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime-opt-1920.WEBP 1920w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<p>위의 그림은 크롬의 자바스크립트 런타임을 표현한 그림입니다. 이후에 이야기할 포스팅 내용들은 크롬의 자바스크립트 런타임을 기준으로 설명하도록 하겠습니다.</p>
<p>자바스크립트 런타임은 자바스크립트 엔진, Web API, 콜백 큐, 이벤트 루프, 렌더 큐로 구성됩니다. 렌더 큐는 포스팅 마지막의 부록에서 자세히 설명하도록 하겠습니다.</p>
<h3 id="자바스크립트-엔진-v8">자바스크립트 엔진: V8<a class="anchor after" aria-hidden="true" tabindex="-1" href="#자바스크립트-엔진-v8"><span class="anchor-icon">#</span></a></h3>
<p>자바스크립트 런타임을 자바스크립트 엔진을 포함하고 있습니다. 크롬은 자바스크립트 엔진으로 <a href="https://v8.dev/">V8</a>을 사용하고 있습니다.</p>
<p><img src="/assets/img/posts/javascript/v8.png" alt="V8 엔진 로고" title="#width=250px;" loading="lazy" decoding="async" width="1200" height="1200" srcset="/assets/img/posts/javascript/nextImageExportOptimizer/v8-opt-640.WEBP 640w, /assets/img/posts/javascript/nextImageExportOptimizer/v8-opt-1080.WEBP 1080w, /assets/img/posts/javascript/nextImageExportOptimizer/v8-opt-1920.WEBP 1920w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<p>V8은 구글에서 개발한 오픈소스 자바스크립트 엔진입니다. C++로 만들어져 있으며, Node.js, 크롬 브라우저 등에서 사용됩니다.</p>
<p>V8은 싱글 스레드를 제공합니다. 싱글 스레드는 하나의 콜 스택(Call Stack)과 하나의 힙(Heap)을 제공합니다. 콜 스택은 위에서 이야기했듯이 함수의 호출 순서를 저장합니다. 힙은 할당된 메모리들이 저장되는 영역입니다.</p>
<p>하나의 콜 스택을 가지고 있다는 말은 한 번에 하나의 동작만 할 수 있다는 의미입니다. 하지만 버젓이 <code>setTimeout</code>이나 <code>ajax</code>(HTTP 요청), DOM 이벤트 등 콜백으로 비동기 동작을 하도록 코딩하고 있습니다. 심지어 V8 소스에는 이러한 메서드들이 정의되어 있지도 않습니다.</p>
<p><code>setTimeout(..., 5000)</code>가 호출되었을 때, 누가 5초를 카운트하고 5초 후에 콜백 함수를 실행시키는 걸까요? 이 역할을 하는 친구가 바로 Web API입니다.</p>
<h3 id="web-api">Web API<a class="anchor after" aria-hidden="true" tabindex="-1" href="#web-api"><span class="anchor-icon">#</span></a></h3>
<p>Web API는 자바스크립트 엔진에서 정의되지 않았던 <code>setTimeout</code>이나 HTTP 요청 메서드, DOM 이벤트 등의 메서드를 지원합니다.</p>
<h3 id="콜백-큐">콜백 큐<a class="anchor after" aria-hidden="true" tabindex="-1" href="#콜백-큐"><span class="anchor-icon">#</span></a></h3>
<p>콜백 큐는 Web API 결괏값을 쌓아 두는 큐입니다. 예를 들어 자바스크립트에서 <code>setTimeout(cb, 5000)</code>를 호출하게 되면, Web API는 타이머를 동작시켜 5초 후에 콜백 큐에, <code>cb</code>을 쌓습니다.</p>
<h3 id="이벤트-루프">이벤트 루프<a class="anchor after" aria-hidden="true" tabindex="-1" href="#이벤트-루프"><span class="anchor-icon">#</span></a></h3>
<p>이벤트 루프는 콜 스택과 콜백 큐를 관찰하는 역할을 합니다. 콜 스택이 비어 있으면 콜백 큐의 첫 번째 콜백을 스택에 쌓습니다.</p>
<h2 id="자바스크립트-런타임-동작-예제">자바스크립트 런타임 동작 예제<a class="anchor after" aria-hidden="true" tabindex="-1" href="#자바스크립트-런타임-동작-예제"><span class="anchor-icon">#</span></a></h2>
<p>지금까지의 이야기한 자바스크립트 엔진, Web API, 콜백 큐, 이벤트 루프의 관계를 좀 더 이해하기 쉽도록 예제를 통해 설명해 보도록 하겠습니다.</p>
<h3 id="settimeout"><code>setTimeout</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#settimeout"><span class="anchor-icon">#</span></a></h3>
<p><img src="/assets/img/posts/javascript/javascript_runtime_settimeout.gif" alt="자바스크립트 런타임 예제" loading="lazy" decoding="async" width="1498" height="990" srcset="/assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime_settimeout-opt-640.WEBP 640w, /assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime_settimeout-opt-1080.WEBP 1080w, /assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime_settimeout-opt-1920.WEBP 1920w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<h4 id="참고-settimeout은-동작하는-최소-시간을-보장한다">참고: setTimeout은 동작하는 최소 시간을 보장한다<a class="anchor after" aria-hidden="true" tabindex="-1" href="#참고-settimeout은-동작하는-최소-시간을-보장한다"><span class="anchor-icon">#</span></a></h4>
<p>setTimeout는 정확히 얼마 후 동작하겠다는 의미가 아니라 얼마 후 동작하는 최소 시간을 보장한다는 의미가 더 정확합니다. 왜냐하면 정해진 시간 후 콜백이 콜백 큐에 쌓이는데, 콜백 큐에 쌓인 콜백이 콜 스택에 들어오기 위해서는 콜 스택이 비어 있어야 합니다. 정해진 시간이 지난 후 그 이후에 콜 스택이 비어있을 때 setTimeout의 콜백이 실행됩니다.</p>
<h3 id="settimeout-0"><code>setTimeout(..., 0)</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#settimeout-0"><span class="anchor-icon">#</span></a></h3>
<p><img src="/assets/img/posts/javascript/javascript_runtime_settimeout_0.gif" alt="자바스크립트 런타임 예제" loading="lazy" decoding="async" width="1498" height="990" srcset="/assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime_settimeout_0-opt-640.WEBP 640w, /assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime_settimeout_0-opt-1080.WEBP 1080w, /assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime_settimeout_0-opt-1920.WEBP 1920w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<p><code>setTimeout(..., 0)</code> 0초 후 실행을 시킨다는 의미입니다. 즉시 실행될 것 같지만 실제로는 즉시 실행되지 않습니다. 그 이유는 콜 스택이 비어있지 않기 때문입니다. 이벤트 루프는 콜 스택이 비어있을 때까지 기다리다가 콜 스택이 비게 되면 콜백 큐의 첫 번째 콜백을 스택에 쌓습니다.</p>
<p>즉 <code>setTimeout(..., 0)</code>는 스택이 비어있을 때까지 기다린 후 호출되어야 할 때 사용될 수 있습니다.</p>
<h3 id="ajax"><code>ajax</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#ajax"><span class="anchor-icon">#</span></a></h3>
<p><code>ajax</code>도 <code>setTimeout</code>과 동일하게 동작합니다.</p>
<p><img src="/assets/img/posts/javascript/javascript_runtime_ajax.gif" alt="자바스크립트 런타임 예제" loading="lazy" decoding="async" width="1498" height="990" srcset="/assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime_ajax-opt-640.WEBP 640w, /assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime_ajax-opt-1080.WEBP 1080w, /assets/img/posts/javascript/nextImageExportOptimizer/javascript_runtime_ajax-opt-1920.WEBP 1920w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<h2 id="부록-렌더-큐">부록: 렌더 큐<a class="anchor after" aria-hidden="true" tabindex="-1" href="#부록-렌더-큐"><span class="anchor-icon">#</span></a></h2>
<p>렌더 큐는 이벤트 큐와 유사합니다. 렌더 큐와 이벤트 큐의 차이점은 렌더 큐가 이벤트 큐 보다 더 높은 우선순위를 가진다(렌더 큐의 콜백이 먼저 콜 스택에 들어가게 된다)는 점입니다.</p>
<p><img src="/assets/img/posts/javascript/render_queue.png" alt="렌더 큐" loading="lazy" decoding="async" width="1294" height="1100" srcset="/assets/img/posts/javascript/nextImageExportOptimizer/render_queue-opt-640.WEBP 640w, /assets/img/posts/javascript/nextImageExportOptimizer/render_queue-opt-1080.WEBP 1080w, /assets/img/posts/javascript/nextImageExportOptimizer/render_queue-opt-1920.WEBP 1920w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<p>위의 그림은 자바스크립트 런타임에 렌더 큐를 추가한 그림입니다.</p>
<p>브라우저는 1초에 60프레임 속도로 화면을 다시 그립니다(Repaint). 하지만 자바스크립트가 하는 일들로 인해 Repaint 작업에 영향을 받습니다. 렌더도 큐에 쌓여 있는 하나의 콜백처럼 동작하기 때문에, 콜 스택에 코드가 있으면 렌더링 하지 못합니다.</p>
<p>느린 동기식 루프를 실행하면, 콜 스택에 코드가 쌓여있기 때문에 렌더가 동작하지 않습니다. 이벤트 루프를 막지 말라고 하는 것이 이러한 현상을 뜻합니다. 콜 스택에 쓸데없는 느린 코드를 쌓아서 브라우저가 할 일(렌더링)을 못 하게 하는 일이 없어야 합니다. 단위가 큰 코드는 작은 단위로 쪼개거나, 오래 걸리는 작업들은 비동기로 동작시키는 것이 좋습니다.</p>
