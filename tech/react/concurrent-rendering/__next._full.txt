<h2 id="동시성concurrency과-병렬성parallelism">동시성(Concurrency)과 병렬성(Parallelism)<a class="anchor after" aria-hidden="true" tabindex="-1" href="#동시성concurrency과-병렬성parallelism"><span class="anchor-icon">#</span></a></h2>
<p>동시성과 병렬성은 동시에 둘 이상의 작업을 처리하는 방법이라는 공통점이 있지만 동작하는 방식에 차이가 있습니다.</p>
<ul>
<li><strong>동시성</strong>: 하나의 코어에서 둘 이상의 작업을 여러 조각으로 나누어 Context Switch를 통해 번갈아가며 실행하여 여러 개의 작업이 동시에 처리되는 것처럼 보이게 하는 것을 말합니다.</li>
<li><strong>병렬성</strong>: 여러 개의 코어에서 각각의 작업을 담당하여 처리하는 것을 말합니다.</li>
</ul>

<h2 id="긴급한-업데이트urgent-updates와-전환-업데이트transition-updates">긴급한 업데이트(Urgent updates)와 전환 업데이트(Transition updates)<a class="anchor after" aria-hidden="true" tabindex="-1" href="#긴급한-업데이트urgent-updates와-전환-업데이트transition-updates"><span class="anchor-icon">#</span></a></h2>
<p>React 18 이전에서는 렌더링을 쪼갤 수 없는 하나의 작업이었습니다. 그래서 렌더링이 시작되면 렌더링을 멈출 방법이 없었고 렌더링이 오래 걸린다면 다음에 수행해야 하는 작업들이 진행을 하지 못하면서 애플리케이션이 버벅거리는 현상이 발생했습니다. React 18에서는 동시성 렌더링을 사용하여 급한 작업과 덜 급한 작업으로 나눠, 급한 작업을 우선 화면에 렌더링 하는 방법으로 사용성 개선을 했습니다.</p>
<p>아래 그림은 구글 메인 페이지에서 검색어를 입력할 경우 노출되는 화면입니다. 사용자의 입력을 받는 input 컴포넌트와 검색 결과를 나타내는 목록 컴포넌트로 나눌 수 있습니다.</p>
<p><img src="/assets/img/posts/react/search_box.png" alt="긴급한 업데이트와 전환 업데이트" loading="lazy" decoding="async" width="600" height="470" srcset="/assets/img/posts/react/nextImageExportOptimizer/search_box-opt-640.WEBP 640w" sizes="(max-width: 640px) 100vw, 1000px"></p>
<p>사용자의 입력을 받는 input 컴포넌트는 버벅거림 없이 즉시 사용자에게 노출되어야 하지만, 검색 결과를 나타내는 목록 컴포넌트는 즉시 검색 결과를 노출하지 않아도 됩니다. 따라서 input 컴포넌트의 업데이트는 급한 작업, 긴급한 업데이트(urgent updates)로 목록 컴포넌트의 업데이트는 덜 급한 작업, 전환 업데이트(transition updates)로 나눌 수 있습니다.</p>

<h3 id="usedeferredvalue-훅"><code>useDeferredValue</code> 훅<a class="anchor after" aria-hidden="true" tabindex="-1" href="#usedeferredvalue-훅"><span class="anchor-icon">#</span></a></h3>
<p><code>useDeferredValue</code> 훅은 <code>startTransition</code> 함수와 동일하게 전환 업데이트 처리를 합니다. <code>useDeferredValue</code> 훅의 반환 값(<code>deferredValue</code>)으로 화면이 업데이트되는 경우에 지연처리 됩니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="ts"><code><span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">const</span><span style="color:#023B95;--shiki-dark:#91CBFF"> deferredValue</span><span style="color:#A0111F;--shiki-dark:#FF9492"> =</span><span style="color:#622CBC;--shiki-dark:#DBB7FF"> useDeferredValue</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(value)</span></span></code></pre>
<ul>
<li><code>value: any</code>: 지연하려는 값입니다. 모든 타입이 올 수 있습니다.</li>
<li><code>deferredValue: any</code>: 지연된 값입니다.</li>
</ul>
<p><code>startTransition</code> 함수를 사용하기 위해서는 set 함수를 사용해야 하는데, set 함수에 접근할 수 없거나 컴포넌트가 전달받은 props를 지연하고 싶을 경우 <code>useDeferredValue</code> 훅을 사용할 수 있습니다.</p>
<p><code>Object.is</code> 비교를 통해 현재 화면에 그리고 있는 값과 다른 값을 전달받으면 백그라운드에서 리렌더링을 진행합니다. 백그라운드에서 리렌더링 중에 새로운 값을 전달받으면 진행 중이던 렌더링은 취소되고 처음부터 다시 렌더링 합니다.</p>
<p><code>useTransition</code> 훅과 다르게 지연 중임을 나타내는 값을 반환하지 않는데, 아래 코드와 같은 방법을 사용하여 지연 중임을 알 수 있습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="tsx"><code><span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">const</span><span style="color:#023B95;--shiki-dark:#91CBFF"> deferredQuery</span><span style="color:#A0111F;--shiki-dark:#FF9492"> =</span><span style="color:#622CBC;--shiki-dark:#DBB7FF"> useDeferredValue</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(query);</span></span>
