<h2 id="정리">정리<a class="anchor after" aria-hidden="true" tabindex="-1" href="#정리"><span class="anchor-icon">#</span></a></h2>
<ul>
<li><strong>생태계</strong> 측면에서, 생태계의 크기에서 <code>react-hook-form</code>이냐, <code>formik</code>냐 2개의 선택지로 좁혀졌다고 생각됩니다.</li>
<li><strong>사용성</strong> 측면에서, 예제 코드에서는 <code>formik</code>에서 제공하는 컴포넌트를 사용하여 코드 양을 줄이는 방향으로 코드를 작성하였지만, <a href="https://formik.org/docs/api/useFormik"><code>formik</code>는 훅 형태의 사용성</a>을 제공하여 훅을 사용하면 <code>react-hook-form</code>과 유사한 사용성을 가지게 됩니다. 사용성 측면에서 <code>react-hook-form</code>과 <code>formik</code>의 우열을 가리기는 어려웠습니다.</li>
<li><strong>성능</strong> 측면에서, <code>react-hook-form</code>은 번들 크기가 작아 첫 렌더링 속도가 빠르고, 리렌더링 횟수가 월등히 적기 때문에 성능 측면으로 본다면 <code>react-hook-form</code>이 더 좋은 선택으로 보입니다.</li>
<li><strong>유연성</strong> 측면에서, <code>react-hook-form</code>은 Uncontrolled 방식으로 성능에 이점이 있지만 폼 값을 컨트롤하기 어려운 측면이 있습니다. 이 단점을 보완하기 위해 <code>watch</code>라는 기능이 존재하지만, <code>formik</code>는 Controlled 방식이기 때문에 폼 값을 좀 더 유연성 있게 다룰 수 있어 유연성 측면에서는 <code>formik</code>가 더 좋은 선택으로 보입니다.</li>
</ul>

<p>Uncontrolled 아코디언 컴포넌트는 <code>펼치기</code> 상태 값을 내부에서 가지고 있기 때문에 펼쳐지거나 접힐 때 Uncontrolled 아코디언만 리렌더링 되지만, Controlled 아코디언 컴포넌트는 <code>펼치기</code> 상태 값을 부모에서 가지고 있기 때문에 펼쳐지거나 접힐 때 부모 컴포넌트를 포함한 모든 하위 컴포넌트가 리렌더링 됩니다.</p>
<p>Uncontrolled 아코디언 컴포넌트의 경우 펼쳐져 있는 상태인지, 접혀 있는 상태인지 부모 컴포넌트는 알 수 없지만 Controlled 아코디언 컴포넌트의 경우 펼쳐져 있는 상태인지, 접혀 있는 상태인지를 부모 컴포넌트가 알 수 있기 때문에 Controlled 아코디언 컴포넌트가 좀 더 유연한 사용성을 가지게 됩니다.</p>
