<li>React Hook Form은 Uncontrolled 방식의 빠른 성능이 장점인 폼 관리 라이브러리입니다. 물론 Controlled 방식도 지원합니다.
<ul>
<li>Uncontrolled 방식은 <code>register</code> 함수를 사용합니다.
<ul>
<li><code>register</code> 함수의 두 번째 파라미터를 사용하여 유효성 검증이 가능합니다.</li>
</ul>
</li>
<li>Controlled 방식은 <code>Controller</code> 컴포넌트를 사용합니다.
<ul>
<li><code>Controller</code> 컴포넌트를 사용하여 MUI 등의 UI 라이브러리와 함께 사용이 가능합니다.</li>
<li><code>Controller</code> 컴포넌트의 <code>rules</code> 속성을 사용하여 유효성 검증이 가능합니다.</li>
</ul>
</li>
</ul>
</li>

<ul>
<li><code>register</code>: Uncontrolled 방식으로 사용하기 위해 사용됩니다. 요소의 속성으로 전달되어야 하는 값들을 반환하는 함수입니다.</li>
<li><code>control</code>: Controlled 방식으로 사용하기 위해 사용됩니다. UI 라이브러리와 함께 사용할 때 자주 사용됩니다.</li>
<li><code>handleSubmit</code>: 유효성 검증을 통과한 사용자 입력 값을 전달받기 위한 함수입니다.</li>
<li><code>watch</code>: 사용자 입력 값의 변화를 감시하기 위한 함수입니다.</li>
<li><code>formState</code>: 폼의 상태를 저장하는 객체로, 대표적으로 <code>errors</code> 객체를 통해 에러 정보를 가져올 수 있습니다.</li>
</ul>
</li>
<li><code>Controller</code> 컴포넌트를 사용하면 UI 라이브러리와 React Hook Form을 함께 사용할 수 있습니다. 아래는 중요한 속성입니다.
<ul>
<li><code>name</code>: 요소를 구분하기 위한 값으로 같은 폼으로 묶여 있는 요소끼리 유니크해야 합니다.</li>

</li>

</ul>

<p>React Hook Form은 사용자 입력을 받고 검증하는 것을 도와주는 라이브러리로, React에서 폼을 관리하는 가장 유명한 라이브러리 중 하나입니다. React Hook Form을 사용하면 사용자에게 입력을 받고 검증하는데 드는 시간을 줄일 뿐만 아니라 더불어 성능까지 두 마리 토끼를 모두 잡을 수 있습니다.</p>
<p>React Hook Form은 Uncontrolled 방식을 사용하는 폼 관리 라이브러리로 빠른 성능이 장점 중 하나입니다. 다른 폼 관리 라이브러리와 비교하고 싶다면, <a href="/tech/react/form-libraries/">[React] react-hook-form, formik, rc-field-form 폼 관리 어떤 걸로 해야 할까</a>를 참고 부탁드립니다.</p>

<iframe src="https://codesandbox.io/embed/react-hook-form-register-error-message-3x7pjx?fontsize=14&#x26;hidenavigation=1&#x26;theme=dark" style="width:100%; height:500px; border:0; border-radius: 10px; overflow:hidden;" title="React Hook Form - register error message" allow="accelerometer; ambient-light-sensor; camera; encrypted-media; geolocation; gyroscope; hid; microphone; midi; payment; usb; vr; xr-spatial-tracking" sandbox="allow-forms allow-modals allow-popups allow-presentation allow-same-origin allow-scripts" loading="lazy"></iframe>
</div>
<p><code>register</code> 함수의 두 번째 파라미터 중 <code>maxLength</code> 와 같은 유효성 검증 필드는 유효성 체크를 위한 <code>value</code> 필드와 메시지 출력을 위한 <code>message</code> 필드를 포함한 객체(<code>{ value: string | number | boolean | RegExp, message: string }</code>)를 전달하면 메시지 출력이 가능합니다. <code>required</code> 체크만 <code>string</code> 타입을 전달하면 전달한 문자열이 에러 메시지로 노출됩니다. 유효성 검증을 위한 자세한 옵션 정보는 <a href="/tech/react/react-hook-form/#uncontrolled%EC%9D%98-%EA%B2%BD%EC%9A%B0-register-%ED%95%A8%EC%88%98">RegisterOptions 타입</a>을 참고 바랍니다.</p>
<h3 id="controller-컴포넌트의-경우-1"><code>Controller</code> 컴포넌트의 경우<a class="anchor after" aria-hidden="true" tabindex="-1" href="#controller-컴포넌트의-경우-1"><span class="anchor-icon">#</span></a></h3>
<p><code>Controller</code> 컴포넌트를 사용한 경우 <code>render</code> 함수의 <code>fieldState.error</code> 필드를 사용하면 아래 코드와 같이 에러 메시지를 화면에 노출할 수 있습니다. <code>register</code> 함수의 두 번째 파라미터에 전달했던 값과 동일한 값을 <code>Controller</code> 컴포넌트의 <code>rules</code> prop에 전달하면 됩니다.</p>
<div>
<iframe src="https://codesandbox.io/embed/react-hook-form-controller-error-message-kqyx5t?fontsize=14&#x26;hidenavigation=1&#x26;theme=dark" style="width:100%; height:500px; border:0; border-radius: 10px; overflow:hidden;" title="React Hook Form - Controller error message" allow="accelerometer; ambient-light-sensor; camera; encrypted-media; geolocation; gyroscope; hid; microphone; midi; payment; usb; vr; xr-spatial-tracking" sandbox="allow-forms allow-modals allow-popups allow-presentation allow-same-origin allow-scripts" loading="lazy"></iframe>
</div>
<p><code>formState.errors</code>에는 React Hook Form을 사용한 모든 요소의 에러 값이 담겨오지만, <code>Controller</code> 컴포넌트의 <code>render</code> 함수의 <code>fieldState.error</code>에는 <code>Controller</code> 컴포넌트의 <code>name</code> 속성에 정의한 하나의 요소의 에러 값만 담겨오게 됩니다.</p>
<h3 id="외부-유효성-검증-라이브러리와-함께-1">외부 유효성 검증 라이브러리와 함께<a class="anchor after" aria-hidden="true" tabindex="-1" href="#외부-유효성-검증-라이브러리와-함께-1"><span class="anchor-icon">#</span></a></h3>
<p><code>@hookform/resolvers</code> 라이브러리를 사용하면 외부 유효성 검증 라이브러리와 함께 React Hook Form을 사용할 수 있는데, 이때 에러 메시지를 설정하는 방법은 사용한느 유효성 검증 라이브러리의 스펙을 동일하게 따라가면 됩니다. 아래 코드는 <code>Yup</code>을 사용하여 유효성 검증한 에러 메시지를 노출하는 예제입니다.</p>

<h2 id="종속성-있는-유효성-검증">종속성 있는 유효성 검증<a class="anchor after" aria-hidden="true" tabindex="-1" href="#종속성-있는-유효성-검증"><span class="anchor-icon">#</span></a></h2>
<p>많은 폼 요소를 다루다 보면 종종 서로 종속성이 있는 유효성 검증이 필요할 때가 있습니다. 예를 들어 비밀번호 입력 태그와 비밀번호 확인 태그 2개가 있고, 비밀번호 확인 태그는 비밀번호 입력 태그가 변경될 경우 유효성 검증을 다시 해야 하는 상황이 있습니다. 이렇게 종속성이 있는 유효성 검증을 <code>register</code> 함수와 <code>Controller</code> 컴포넌트에서 처리하는 방법을 살펴보도록 하겠습니다.</p>
<h3 id="register-함수의-경우-2"><code>register</code> 함수의 경우<a class="anchor after" aria-hidden="true" tabindex="-1" href="#register-함수의-경우-2"><span class="anchor-icon">#</span></a></h3>
<p><code>register</code> 함수의 두 번째 파라미터인 <code>RegisterOptions</code>의 <code>deps</code> 옵션을 사용하면 아래 코드와 같이 종속성 있는 유효성 검증을 할 수 있습니다.</p>
<div>
<iframe src="https://codesandbox.io/embed/react-hook-form-register-deps-wqfs7w?fontsize=14&#x26;hidenavigation=1&#x26;theme=dark" style="width:100%; height:500px; border:0; border-radius: 10px; overflow:hidden;" title="React Hook Form - register deps" allow="accelerometer; ambient-light-sensor; camera; encrypted-media; geolocation; gyroscope; hid; microphone; midi; payment; usb; vr; xr-spatial-tracking" sandbox="allow-forms allow-modals allow-popups allow-presentation allow-same-origin allow-scripts" loading="lazy"></iframe>

<p><code>watch</code>를 사용하면 값이 업데이트된 것을 감시할 수 있는데, <code>watch</code>는 종속성 있는 유효성 검증 등 여러 상황에서 유용하게 사용할 수 있습니다.</p>
<h3 id="controller-컴포넌트의-경우-2"><code>Controller</code> 컴포넌트의 경우<a class="anchor after" aria-hidden="true" tabindex="-1" href="#controller-컴포넌트의-경우-2"><span class="anchor-icon">#</span></a></h3>
<p><code>Controller</code> 컴포넌트의 <code>rules</code> prop에는 <code>RegisterOptions</code>가 동일하게 사용되기 때문에 아래 코드와 같이 <code>rules</code> 속성에 <code>RegisterOptions</code>의 <code>deps</code>를 사용하면 종속성 있는 유효성 검증을 할 수 있습니다.</p>

<h3 id="formprovider-컴포넌트"><code>FormProvider</code> 컴포넌트<a class="anchor after" aria-hidden="true" tabindex="-1" href="#formprovider-컴포넌트"><span class="anchor-icon">#</span></a></h3>
<p><code>useForm</code>의 반환 값을 자식 컴포넌트에게 전달해 줘야 할 때가 종종 있습니다. 컴포넌트의 트리 구조가 간단하다면 간단하게 속성으로 전달이 가능하지만, 컴포넌트 트리 구조가 복잡해져서 자식의 자식 컴포넌트로, 그리고 여러 컴포넌트로 반환 값을 전달해야 한다면 이 작업은 번거로운 일이 됩니다. React Hook Form은 이런 props 전달의 번거로움을 줄이기 위해서 <code>FormProvider</code> 컴포넌트와 <code>useFormContext</code>를 사용하는 Context를 제공합니다. 아래 코드와 같이 사용할 수 있습니다.</p>

<ul>
<li><code>name: string</code>: 요소의 이름값입니다.</li>
<li><code>errors: object</code>: <code>register</code> 함수의 <code>formState.errors</code>나 <code>Controller</code> 컴포넌트의 <code>render</code> 함수의 <code>formState.errors</code> 객체가 와야 합니다. <code>FormProvider</code>을 사용한다면 생략 가능합니다.</li>
<li><code>message: string | React.ReactElement</code>: 에러 메시지가 설정되어 있지 않을 때 노출 되는 기본 에러 메시지입니다.</li>
<li><code>as: React.ElementType | string</code>: 어떤 요소로 랜더링 할지 선택하는 값입니다. <code>as="span"</code>, <code>as={&#x3C;Text />}</code>와 같이 컴포넌트나 HTML 태그 모두 가능합니다.</li>
<li><code>render: ({ message: string | React.ReactElement, messages?: Object}) => any</code>: 에러 메시지를 랜더링 하기 위한 랜더링 함수입니다. <code>render</code> 함수를 사용하여 에러 메시지를 좀 더 유연하게 커스텀할 수 있습니다.
<ul>
<li><code>messages</code>의 경우 <code>useForm</code> 훅의 <code>criteriaMode</code> 옵션을 <code>all</code>로 설정할 경우 사용할 수 있습니다.</li>
</ul>
</li>
</ul>
