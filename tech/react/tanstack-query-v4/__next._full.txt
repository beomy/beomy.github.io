1d:T2a9f8,<p>TanStack Query는 비동기 작업 처리를 돕는 라이브러리입니다. v3까지는 React Query라는 이름으로 React만 지원했는데, v4 부터 React 이외의 프레임워크(Vue, Svelte, Solid)에서 사용할 수 있도록 업데이트 되며 TanStack Query로 이름이 변경되었습니다. 이번 포스트에서는 React에서 TanStack Query를 사용하는 방법을 살펴보도록 하겠습니다. TanStack의 <code>react-query</code>를 가져와 사용하는데, 이번 포스트에서는 React Query라는 명칭을 사용하도록 하겠습니다.</p>
<h2 id="역할">역할<a class="anchor after" aria-hidden="true" tabindex="-1" href="#역할"><span class="anchor-icon">#</span></a></h2>
<p>React Query는 서버의 데이터 가져오기/업데이트, 캐싱, 에러 처리 등을 쉽게 할 수 있도록 돕는 라이브러리입니다. 서버에서 가져온 값을 담는 객체, 에러가 발생했을 때 에러 정보를 담는 객체, 데이터 가져오기/엡데이트 중임을 나타내는 등 각종 유틸 기능을 제공합니다. 동일한 요청을 동시에 여러번 해도 한번만 요청을 보내어 최적화 하기 때문에 비동기 작업(API 호출하는 등...)을 좀 더 효율적이고 간단하게 처리할 수 있게 합니다.</p>

<h2 id="기본-개념">기본 개념<a class="anchor after" aria-hidden="true" tabindex="-1" href="#기본-개념"><span class="anchor-icon">#</span></a></h2>
<p>React Query를 사용할 때 자주 접하게 되는 React Query의 중요한 개념들과 설정들을 살펴보도록 하겠습니다.</p>
<h3 id="query와-mutation">Query와 Mutation<a class="anchor after" aria-hidden="true" tabindex="-1" href="#query와-mutation"><span class="anchor-icon">#</span></a></h3>
<p>React Query를 사용하다 보면 Query와 Mutation이라는 단어를 많이 접하게 됩니다. Query는 서버에서 데이터를 가져오는 작업으로 <code>useQuery</code> 훅을 많이 사용합니다. Mutation은 서버의 데이터를 변경하는 부수효과가 있는 작업으로 <code>useMutation</code> 훅을 많이 사용힙니다. 보통은 HTTP 메소드의 GET 요청의 경우 <code>useQuery</code>를 POST, PUT, PATCH, DELETE 요청의 경우 <code>useMutation</code>을 사용하게 됩니다.</p>
<p><code>useQueries</code>와 <code>useInfiniteQuery</code> 훅은 <code>useQuery</code>와 동일하게 서버에서 데이터를 가져올 때 사용되는 훅입니다. 여러 데이터를 병렬로 가져와야 할 때는 <code>useQueries</code> 훅을 사용 할 수 있고, 무한 스크롤과 같이 계속해서 데이터를 가져와야 할 경우 <code>useInfiniteQuery</code> 훅을 사용할 수 있습니다.</p>
<h3 id="다시-가져오기">다시 가져오기<a class="anchor after" aria-hidden="true" tabindex="-1" href="#다시-가져오기"><span class="anchor-icon">#</span></a></h3>
<p>Query(<code>useQuery</code>, <code>useQueries</code>, <code>useInfiniteQuery</code>)는 설정 값에 따라 다르지만 기본 값으로 설정된 경우 오래된 쿼리는 아래와 같은 경우에 자동으로 데이터를 다시 가져옵니다.</p>
<ul>
<li>쿼리를 사용한 컴포넌트가 마운트 되었을 때</li>
<li>윈도우가 다시 포커스 되었을 때</li>
<li>네트워크가 다시 연결되었을 때</li>
<li><code>refetchInterval</code> 설정 하여 반복적으로 refetch 되도록 설정 했을 때</li>
</ul>
<h3 id="retry"><code>retry</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#retry"><span class="anchor-icon">#</span></a></h3>
<p><code>retry</code> 설정에 따라 Query/Mutation 작업이 실패하면 React Query는 자동으로 재시도를 합니다. Query의 <code>retry</code> 기본 값은 3, Mutation의 <code>retry</code> 기본 값은 0입니다. <code>retryDelay</code> 설정을 통해 얼마 간의 간격으로 재시도를 할 것인지 설정할 수 있습니다. <code>retry</code>와 <code>retryDelay</code>는 Query, Mutation 훅(<code>useQuery</code>, <code>useMutation</code>, <code>useQueries</code>, <code>useInfiniteQuery</code> 훅)의 옵션으로 전달하여 설정할 수 있습니다.</p>
<h3 id="staletime"><code>staleTime</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#staletime"><span class="anchor-icon">#</span></a></h3>
<p><code>staleTime</code>은 Query를 통해 가져온 데이터가 오래된 것으로 인식하게 되는 시간입니다. ms 단위로 저장되는데 기본 값은 0입니다. Query는 오래된 데이터라고 판단되면 다시 데이터를 가져옵니다. <code>staleTime</code>에 설정된 시간 따라 Query가 동작 하는 방식은 아래와 같습니다.</p>
<ul>
<li>0으로 설정할 경우: 데이터를 가져온 즉시 오래된 데이터로 인식하기 때문에 캐시 된 데이터를 우선 사용한 후 API를 다시 호출하여 새로운 데이터를 응답 받으면 데이터를 교체합니다.</li>
<li>5000으로 설정할 경우
<ul>
<li>5초 이전에 데이터를 요청한 경우: 최신 데이터로 판단하여 API를 다시 호출하지 않고 캐시된 데이터를 사용합니다.</li>
<li>5초 이후에 데이터를 요청한 경우: 캐시 된 데이터를 오래된 데이터로 판단하여 캐시 된 데이터를 우선 사용한 후, API를 호출하여 새로운 데이터를 응답 받으면 데이터를 교체하고 응답 받은 데이터를 캐시합니다.</li>
</ul>
</li>
</ul>
<p><code>staleTime</code>은 데이터를 다시 가져올지 판단하는 설정입니다. Query 훅(<code>useQuery</code>, <code>useMutation</code>, <code>useQueries</code> 훅)의 옵션으로 전달하여 설정할 수 있습니다. <a href="https://codesandbox.io/s/tanstack-query-staletime-n12m0e">CodeSandBox</a>에서 테스트하실 수 있습니다.</p>
<h3 id="cachetime"><code>cacheTime</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#cachetime"><span class="anchor-icon">#</span></a></h3>
<p><code>cacheTime</code>은 데이터를 얼마나 오랫동안 보관 할 것인지 나타내는 시간입니다. ms 단위로 저장되는데 기본 값은 5분(5 * 60 * 1000)입니다. 쿼리 인스턴스가 unmount 되면 데이터는 비활성화(inactive) 상태가 되는데, 비활성화 된 데이터는 <code>cacheTime</code>에 설정된 시간이 지난 후 가비지 컬렉션 됩니다. <code>cacheTime</code>에 설정된 시간 따라 React Query가 동작 하는 방식은 아래와 같습니다.</p>
<ul>
<li>5000으로 설정할 경우
<ul>
<li>비활성화 된 데이터를 5초 이전에 요청한 경우: 캐시 된 데이터를 우선 사용한 후 API를 호출하여 새로운 데이터를 응답 받으면 응답 받은 데이터를 다시 캐시합니다.</li>
<li>비활성화 된 데이터를 5초 이후에 요청한 경우: 데이터가 이미 가비지 컬렉션 되었기 때문에, 캐시 데이터를 사용하지 못하고 API 응답 데이터를 기다린 후 데이터를 응답 받으면 응답 받은 데이터를 사용하고 캐시합니다.</li>
</ul>
</li>
</ul>
<p><code>cacheTime</code>은 캐시된 값을 사용할지 판단하는 설정입니다. Query, Mutation 훅(<code>useQuery</code>, <code>useMutation</code>, <code>useQueries</code>, <code>useInfiniteQuery</code> 훅)의 옵션으로 전달하여 설정할 수 있습니다. <a href="https://codesandbox.io/s/tanstack-query-cachetime-cr7be7">CodeSandBox</a>에서 테스트하실 수 있습니다.</p>

<h3 id="queryfn와-mutationfn"><code>queryFn</code>와 <code>mutationFn</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#queryfn와-mutationfn"><span class="anchor-icon">#</span></a></h3>
<p><code>queryFn</code>와 <code>mutationFn</code>은 <code>Promise</code> 객체를 반환하는 비동기 작업을 수행하는 함수입니다. React Query는 <code>queryFn</code>혹은 <code>mutationFn</code>을 실행하여 서버 데이터를 가져오거나 업데이트 합니다. <code>useQuery</code> 훅에서는 <code>queryFn</code> 필드에 비동기 함수를 정의하고, <code>useMutation</code> 훅에서는 <code>mutationFn</code> 필드에 비동기 함수를 정의합니다.</p>
<h4 id="에러-처리-방법">에러 처리 방법<a class="anchor after" aria-hidden="true" tabindex="-1" href="#에러-처리-방법"><span class="anchor-icon">#</span></a></h4>
<p><code>queryFn</code>, <code>mutationFn</code>에서 에러가 발행하면 <code>Promise.reject(new Error(message))</code> 혹은 <code>trow new Error(message)</code>로 에러를 처리해 줘야 합니다.</p>
<h4 id="queryfunctioncontext"><code>QueryFunctionContext</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#queryfunctioncontext"><span class="anchor-icon">#</span></a></h4>
<p>쿼리 함수(<code>queryFn</code>와 <code>mutationFn</code>)의 파라미터를 <code>QueryFunctionContext</code>라고 하는데 <code>QueryFunctionContext</code> 객체는 아래와 같은 필드를 가집니다.</p>
<ul>
<li><code>queryKey: QueryKey</code>: 쿼리 키</li>
<li><code>pageParam?: unknown</code>: 무한 쿼리에서 사용되며, 현재 페이지의 파라미터 정보</li>
<li><code>signal?: AbortSignal</code>: 쿼리를 취소하기 위해 사용하는 AbortSignal 인스턴스</li>
<li><code>meta: Record&#x3C;string, unknown> | undefined</code>: 쿼리의 추가 점보를 담는 필드</li>
</ul>
<p><code>QueryFunctionContext</code>를 사용하여 아래 코드와 같이 <code>queryKey</code>를 참고하는 <code>queryFn</code>을 선언할 수 있습니다.</p>

<h2 id="캐싱-라이프-사이클">캐싱 라이프 사이클<a class="anchor after" aria-hidden="true" tabindex="-1" href="#캐싱-라이프-사이클"><span class="anchor-icon">#</span></a></h2>
<p>캐싱 라이프 사이클 과정을 이해하면 React Query를 이해하는데 많은 도움을 줄 수 있습니다.</p>
<ol>
<li><code>A</code>라는 <code>queryKey</code>를 가진 <code>A</code> 쿼리 인스턴스가 <code>mount</code> 됨</li>
<li>네트워크를 통해 데이터를 가져오고(<code>fetch</code>), 가져오는 데이터는 <code>A</code>라는 <code>queryKey</code>로 캐싱 함</li>
<li>이 데이터는 신선한(<code>fresh</code>) 상태에서 <code>staleTime</code>(기본 값 0) 이후 오래된(<code>stale</code>) 상태로 변경됨</li>
<li><code>A</code> 쿼리 인스턴스가 <code>unmount</code> 됨</li>
<li>캐시는 <code>cacheTime</code>(기본 값 5분) 만큰 유지하다가 가비지 컬렉션 됨</li>
<li>만약 <code>cacheTime</code>이 지나기 전, A 쿼리 인스턴스가 신선한(<code>fresh</code>) 상태라면 새롭게 <code>mount</code>되면 캐시된 데이터를 보여줌</li>
</ol>

<h3 id="usequery"><code>useQuery</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#usequery"><span class="anchor-icon">#</span></a></h3>
<p><code>useQuery</code>는 서버의 데이터를 가져오기 위해 사용되는 훅으로 보통 HTTP의 GET 요청시에 사용되는 훅입니다. <code>useQuery</code>는 아래 코드와 같은 형태로 사용됩니다.</p>

<h4 id="stauts-반환"><code>stauts</code> 반환<a class="anchor after" aria-hidden="true" tabindex="-1" href="#stauts-반환"><span class="anchor-icon">#</span></a></h4>
<p>React Query는 요청한 Query 혹은 Mutation의 상태를 알 수 있도록 <code>status</code> 필드를 반환합니다. <code>status</code>는 <code>idle</code>(Mutation 전용), <code>loading</code>, <code>error</code>, <code>success</code> 값 중 하나를 가집니다.</p>
<ul>
<li><code>idle</code>(Mutation 전용): Mutation 함수가 실행되지 않은 초기 상태</li>
<li><code>loading</code>: 캐시된 데이터도 없고, Query(혹은 Mutation)이 끝나지 않은 상태</li>
<li><code>error</code>: Query(혹은 Mutation)에 에러가 발생한 상태, 이 때 <code>error</code> 객체에는 에러 정보들이 담김</li>
<li><code>success</code>: Query(혹은 Mutation)가 성공한 상태, 이 때 <code>data</code> 객체에는 성공한 결과 데이터들이 담김</li>
</ul>
<p><code>status</code> 이외에 React Query는 요청한 Query, Mutation의 상태를 알 수 있는 <code>is</code>로 시작하는 플래그 값들을 반환합니다.</p>
<h3 id="usemutation"><code>useMutation</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#usemutation"><span class="anchor-icon">#</span></a></h3>
<p><code>useMutation</code>은 서버의 데이터를 변경하기 위해 사용되는 훅으로 보통 HTTP의 POST, PUT, DELETE, PATCH 요청과 같이 부수 효과를 발생하는 요청에서 사용되는 훅입니다. <code>useMutation</code>은 아래 코드와 같은 형태로 사용됩니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="tsx"><code><span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">const</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> {</span></span>

<p><code>useMutation</code>의 반환 값으로 <code>mutation</code>과 <code>mutationAsync</code> 함수가 있는데, 이 함수를 호출하여 Mutation 요청을 할 수 있습니다. <code>mutation</code>와 <code>mutationAsync</code> 함수의 차이점은 <code>mutation</code> 함수는 요청에 응답 받은 후 결과를 <code>onSuccess</code>, <code>onSettled</code>, <code>onError</code>와 같은 콜백 함수로 처리할 수 있고, <code>mutationAsync</code> 함수는 <code>Promise</code>를 반환하기 때문에 <code>Promise</code>의 <code>then</code> 혹은 <code>Async await</code> 형태로 처리할 수 있습니다.</p>

<h4 id="fetchnextpage-fetchpreviouspage"><code>fetchNextPage</code>, <code>fetchPreviousPage</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#fetchnextpage-fetchpreviouspage"><span class="anchor-icon">#</span></a></h4>
<p><code>useInfiniteQuery</code>의 리턴 값 중 <code>fetchNextPage</code>, <code>fetchPreviousPage</code> 필드를 사용하여 이전/다음 데이터를 가져올 수 있습니다.</p>
<ul>
<li><code>fetchNextPage</code>: 다음 페이지 데이터를 가져올 수 있습니다.</li>
<li><code>fetchPreviousPage</code>: 이전 페이지 데이터를 가져올 수 있습니다.</li>
</ul>
<h4 id="getnextpageparam-getpreviouspageparam"><code>getNextPageParam</code>, <code>getPreviousPageParam</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#getnextpageparam-getpreviouspageparam"><span class="anchor-icon">#</span></a></h4>
<p><code>fetchNextPage</code>, <code>fetchPreviousPage</code> 필드를 사용하여 이전/다음 데이터를 가져올 때, <code>getNextPageParam</code>, <code>getPreviousPageParam</code> 옵션을 사용하여 이전/다음 데이터를 가져오기 위한 파라미터를 설정할 수 있습니다.</p>
<ul>
<li><code>getNextPageParam</code>: <code>getNextPageParam</code> 함수에서 리턴 된 값은 <code>fetchNextPage</code> 함수에서 다음 데이터를 가져올 때 사용됩니다.</li>
<li><code>getPreviousPageParam</code>: <code>getPreviousPageParam</code> 함수에서 리턴 된 값은 <code>fetchPreviousPage</code> 함수에서 이전 데이터를 가져올 때 사용됩니다.</li>
</ul>
<h4 id="hasnextpage-haspreviouspage"><code>hasNextPage</code>, <code>hasPreviousPage</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#hasnextpage-haspreviouspage"><span class="anchor-icon">#</span></a></h4>
<p><code>hasNextPage</code>, <code>hasPreviousPage</code> 필드를 통해 이전/다음 데이터가 있는지 확인 할 수 있습니다.</p>
<ul>
<li><code>hasNextPage</code>: 다음 데이터가 존재하면 <code>true</code>, 존재하지 않는다면 <code>false</code>가 됩니다. <code>getNextPageParam</code> 함수의 반환 값이 <code>undefined</code> 이외의 값일 경우 <code>hasNextPage</code>의 값은 <code>true</code>가 됩니다.</li>
<li><code>hasPreviousPage</code>: 이전 데이터가 존재하면 <code>true</code>, 존재하지 않는다면 <code>false</code>가 됩니다. <code>getPreviousPageParam</code> 함수의 반환 값이 <code>undefined</code> 이외의 값일 경우 <code>hasNextPage</code>의 값은 <code>true</code>가 됩니다.</li>
</ul>
<h4 id="isfetchingnextpage-isfetchingpreviouspage"><code>isFetchingNextPage</code>, <code>isFetchingPreviousPage</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#isfetchingnextpage-isfetchingpreviouspage"><span class="anchor-icon">#</span></a></h4>

<li><code>isFetchingPreviousPage</code>: 이전 페이지 데이터를 가져오는 중인지 표시하는 플레그입니다.</li>
</ul>

<h4 id="쿼리-업데이트">쿼리 업데이트<a class="anchor after" aria-hidden="true" tabindex="-1" href="#쿼리-업데이트"><span class="anchor-icon">#</span></a></h4>
<p>대부분의 경우 수동으로 쿼리를 업데이트하지 않고, <code>refetch</code>나 <code>queryClient.invalidateQueries</code>를 사용하여 최신 쿼리를 가져오는 방법을 사용합니다. 하지만 때때로 수동으로 쿼리를 업데이트해 주는 것이 더 좋은 사용성을 제공할 수 있습니다. 수동 쿼리 업데이트는 <code>queryClient.setQueryData</code>를 사용하면 됩니다.</p>
<p>예를 들어, Mutation으로 데이터를 변경 후 Query하여 데이터 사용자에게 변경 후의 데이터를 제공해야 할 때, 변경된 결과를 예상할 수 있지만 Mutation이나 Query가 오래 걸려 사용자에게 늦게 새로운 데이터를 노출하게 된다면, 수동으로 먼저 쿼리를 업데이트 하여 사용자에게 빠르게 변경된 결과를 제공할 수 있습니다. 이런 방식을 Optimistic Updates(낙관적인 업데이트)라고 하는데 아래 코드와 같이 사용할 수 있습니다.</p>

<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">    // optimistic update 한 것이 덮어써지지 않도록 호출한 쿼리를 취소합니다.</span></span>

<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">    // 에러 발생시 복원을 위해 기존 데이터를 저장합니다.</span></span>

<h4 id="쿼리-미리-가져오기">쿼리 미리 가져오기<a class="anchor after" aria-hidden="true" tabindex="-1" href="#쿼리-미리-가져오기"><span class="anchor-icon">#</span></a></h4>
<p><code>queryClient.prefetchQuery</code>를 사용하여 미래에 사용 될 수 있는 쿼리를 미리 가져올 수 있습니다. <code>queryClient.prefetchQuery</code>로 가져오는 데이터가 이미 캐싱되어 있다면 데이터를 가져오지 않습니다. 아래 코드와 같이 사용할 수 있습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="tsx"><code><span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">const</span><span style="color:#622CBC;--shiki-dark:#DBB7FF"> prefetchTodos</span><span style="color:#A0111F;--shiki-dark:#FF9492"> =</span><span style="color:#A0111F;--shiki-dark:#FF9492"> async</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> () </span><span style="color:#A0111F;--shiki-dark:#FF9492">=></span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> {</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  // The results of this query will be cached like a normal query</span></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">  await</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> queryClient.</span><span style="color:#622CBC;--shiki-dark:#DBB7FF">prefetchQuery</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">({</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">    queryKey: [</span><span style="color:#032563;--shiki-dark:#ADDCFF">'todos'</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">],</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">    queryFn: fetchTodos,</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  })</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre>
<p>미리 가져온 쿼리를 캐시를 해두기 때문에 Query를 통해 데이터를 가져올 때 캐시된 데이터를 사용하여 빠른 결과를 얻을 수 있습니다. 예를 들어 1페이지에서 2페이지로 이동했을 때 3페이지의 데이터를 <code>queryClient.prefetchQuery</code>로 미리 캐시해 둔다면 3페이지로 전환할 때 빠른 결과 값을 가져올 수 있습니다.</p>

<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="tsx"><code><span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">useQuery</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">({</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  queryKey: [</span><span style="color:#032563;--shiki-dark:#ADDCFF">'todo'</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">],</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  queryFn: addTodo,</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  suspense: </span><span style="color:#023B95;--shiki-dark:#91CBFF">true</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">,</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">})</span></span></code></pre>
<p><code>suspense</code>의 값으로 <code>boolean</code> 값을 전달 할 수 있습니다. <code>true</code> 값을 전달하면 <code>status === 'loading'</code>, <code>status === 'error'</code>일 때 <code>Suspense</code> 컴포넌트의 <code>fallback</code>이 화면에 노출됩니다. <code>false</code> 값을 전달하면 <code>Suspense</code> 컴포넌트에서 처리되지 않습니다.</p>
