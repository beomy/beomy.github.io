1f:T2f8d2,<p>2023년 10월 TanStack Query v5가 정식 버전으로 릴리즈 되었습니다. 이번 포스터에서는 TanStack Query v5의 React Query를 멋있게 사용할 수 있도록 React Query의 API를 살펴보도록 하겠습니다.</p>
<h2 id="react-query-구조">React Query 구조<a class="anchor after" aria-hidden="true" tabindex="-1" href="#react-query-구조"><span class="anchor-icon">#</span></a></h2>
<p>React Query의 API는 서로 연관이 있는 부분들이 많아, React Query의 구조를 이해하면 API의 역할을 이해하는데 많은 도움을 줄 수 있습니다. 아래 그림은 React Query의 구조를 간단하게 나타낸 그림입니다.</p>

<h2 id="react-query-api-레퍼런스">React Query API 레퍼런스<a class="anchor after" aria-hidden="true" tabindex="-1" href="#react-query-api-레퍼런스"><span class="anchor-icon">#</span></a></h2>
<p>React Query는 다양한 API를 제공해 줍니다. 그중 <code>useQuery</code>, <code>useMutation</code>, <code>useQueryClient</code> 이 3개 훅은 자주 사용되기 때문에, 이 3개의 API는 자세히 살펴보는 것이 좋습니다.</p>
<h3 id="usequery"><code>useQuery</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#usequery"><span class="anchor-icon">#</span></a></h3>
<p><code>useQuery</code>는 React Query에서 가장 많이 사용되는 훅 중 하나입니다. <code>useQuery</code>를 통해 가져온 데이터는 캐시 됩니다. 또한 동일한 <code>queryKey</code>를 사용하는 <code>useQuery</code>가 동시에 여러 번 마운트 되면 최적화되어 한 번만 데이터를 요청합니다. <code>useQuery</code>는 API 서버에서 HTTP의 GET 메서드로 데이터를 가져오는 작업을 할 때 주로 사용됩니다.</p>

<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  structuralSharing, throwOnError,</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">})</span></span></code></pre>
<h5 id="options">Options<a class="anchor after" aria-hidden="true" tabindex="-1" href="#options"><span class="anchor-icon">#</span></a></h5>
<ul>
<li><code>queryKey: unknown[]</code> (<strong>필수</strong>)
<ul>
<li>다른 쿼리와 구분될 수 있는 유니크한 키입니다. 이 값은 쿼리의 해시 키로 사용됩니다.</li>
<li>이 값이 변경되면 자동으로 데이터를 가져옵니다.</li>
</ul>
</li>
<li><code>queryFn: (context: QueryFunctionContext) => Promise&#x3C;TData></code> (<strong>필수</strong>, 단 <code>defaultOptions</code>에서 정의된 경우 생략 가능)
<ul>
<li>데이터를 요청하는 데 사용되는 함수입니다.</li>
<li>파라미터로 <code>context</code>를 받습니다.
<ul>
<li><code>context.queryKey: QueryKey</code>
<ul>
<li><code>queryKey</code>로 전달한 값과 동일한 값입니다.</li>
</ul>
</li>
<li><code>context.signal?: AbortSignal</code>
<ul>
<li>네트워크 요청을 취소하기 위해 사용되는 <a href="https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal">AbortSignal</a> 객체입니다.</li>
</ul>
</li>
<li><code>context.meta: Recode&#x3C;string, unknown> | undefined</code>
<ul>
<li>쿼리에 대한 추가 정보가 담긴 객체입니다.</li>
</ul>
</li>
</ul>
</li>
<li><code>Promise</code>를 반환해야 합니다. <code>undefined</code>를 반환해서는 안됩니다.</li>
</ul>
</li>
<li><code>enabled: boolean</code>
<ul>
<li><code>false</code>으로 설정할 경우 쿼리는 자동으로 데이터를 가져오지 않습니다.</li>
</ul>
</li>
<li><code>networkMode: 'online' | 'always' | 'offlineFirst</code> (default: <code>online</code>)
<ul>
<li><code>online</code>으로 설정할 경우 네트워크에 연결되어 있을 경우에 데이터를 요청합니다.</li>
<li><code>always</code>로 설정할 경우 네트워크 상태와 상관없이 항상 데이터를 요청합니다.</li>
<li><code>offlineFirst</code>로 설정할 경우 데이터를 한번 요청하고 재시도하지 않습니다. <a href="https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Tutorials/js13kGames/Offline_Service_workers">offline-first PWA</a>나 <a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Caching#the_cache-control_header">Cache-Control 헤더</a>로 요청을 캐싱하는 경우 유용한 옵션입니다. 요청을 캐싱하였기 때문에 오프라인에서도 요청은 성공할 수 있습니다. 만약 Cache Miss 되어 요청이 실패되면 <code>online</code> 옵션처럼 동작하여 네트워크가 연결될 때까지 요청을 하지 않습니다.</li>
</ul>
</li>
<li><code>retry: boolean | number | (failureCount: number, error: TError) => boolean</code> (default: CSR은 <code>3</code>, SSR은 <code>0</code>)
<ul>
<li><code>false</code>로 설정할 경우 요청이 실패하면 재시도하지 않습니다.</li>
<li><code>true</code>로 설정할 경우 요청이 실패하면 성공할 때까지 재시도합니다.</li>
<li><code>number</code>형태로 설정할 경우 설정한 값만큼 요청이 실패하면 재시도합니다.</li>
<li>함수 형태로 설정할 경우 함수가 <code>true</code>를 반환하면 재시도하고 <code>false</code>를 반환하면 재시도하지 않습니다.
<ul>
<li><code>failureCount: number</code>는 실패한 횟수를 나타냅니다.</li>
<li><code>error: TError</code>는 에러 정보를 담고 있는 객체입니다.</li>
</ul>
</li>
</ul>
</li>
<li><code>retryOnMount: boolean</code> (default: <code>true</code>)
<ul>
<li><code>false</code>로 설정할 경우 실패했던 쿼리가 다시 마운트 되면 데이터 요청을 재시도하지 않습니다.</li>
</ul>
</li>
<li><code>retryDelay: number | (retryAttempt: number, error: TError) => number</code>
<ul>
<li><code>number</code> 형태로 설정할 경우 설정한 ms 초 이후에 재시도합니다.</li>
<li>함수 형태로 설정할 경우 함수가 반환하는 ms 초 이후에 재시도합니다.
<ul>
<li><code>retryAttempt: number</code>는 정수 값으로 아래와 같이 재시도할 시간을 계산하는 데 사용됩니다.
<ul>
<li><code>attempt => Math.min(attempt > 1 ? 2 ** attempt * 1000 : 1000, 30 * 1000)</code></li>
<li><code>attempt => attempt * 1000</code></li>
</ul>
</li>
<li><code>error: TError</code>는 에러 정보를 담고 있는 객체입니다.</li>
</ul>
</li>
</ul>
</li>
<li><code>staleTime: number | Infinity</code> (default: <code>0</code>)
<ul>
<li>가져온 데이터가 오래된 것으로 판단하는 ms 초입니다. 오래된 데이터로 판단되면 쿼리는 새로운 값을 가져옵니다.</li>
<li><code>Infinity</code>로 설정한 경우 오래된 데이터로 판단하지 않아 최초 1회만 데이터를 가져오게 됩니다.</li>
</ul>
</li>
<li><code>gcTime: number | Infinity</code> (default: CSR은 <code>5 * 60 * 1000</code>(5분), SSR은 <code>Infinity</code>)
<ul>
<li>사용하지 않거나 비활성화된 캐시 데이터가 메모리에 남아 있는 ms 초입니다. 쿼리의 캐시가 사용되지 않거나 비활성화되면 이 ms 초가 지난 후에 가비지 컬렉션(Garbage Cllection)됩니다.</li>
<li><code>Infinity</code>로 설정할 경우 가비지 켈렉션 되지 않아 캐시 데이터가 메모리에서 삭제되지 않습니다.</li>
</ul>
</li>
<li><code>queryKeyHashFn: (queryKey: QueryKey) => string</code>
<ul>
<li><code>queryKey</code>를 사용하여 해시 키를 만들어 반환하는 함수입니다. 반환된 값은 쿼리의 해시 키로 사용됩니다.</li>
</ul>
</li>
<li><code>refetchInterval: number | false | ((query: Query) => number | false | undefined)</code>
<ul>
<li><code>number</code> 형태로 설정할 경우 설정한 ms 초 이후에 데이터를 다시 가져옵니다.</li>
<li><code>false</code>로 설정할 경우 즉시 데이터를 다시 가져옵니다.</li>
<li>함수 형태로 설정할 경우 함수의 반환 값에 따라 데이터를 다시 가져옵니다.</li>
</ul>
</li>
<li><code>refetchIntervalInBackground: boolean</code>
<ul>
<li><code>true</code>로 설정할 경우 <code>refetchInterval</code>를 사용하여 계속 데이터를 다시 가져오게 설정된 쿼리라면 브라우저의 탭이나 창이 백그라운드에 있는 동안에도 계속 데이터를 다시 가져옵니다.</li>
</ul>
</li>
<li><code>refetchOnMount: boolean | "always" | ((query: Query) => boolean | "always")</code> (default: <code>true</code>)
<ul>
<li><code>true</code>로 설정할 경우 데이터가 오래되었다면 쿼리가 마운트 되면 데이터를 다시 가져옵니다.</li>
<li><code>false</code>로 설정할 경우 쿼리가 마운트 될 때 데이터를 다시 가져오지 않습니다.</li>
<li><code>always</code>로 설정할 경우 쿼리가 마운트 될 때 항상 데이터를 다시 가져옵니다.</li>
<li>함수 형태로 설정할 경우 함수의 반환 값에 따라 데이터를 다시 가져옵니다.</li>
</ul>
</li>
<li><code>refetchOnReconnect: boolean | "always" | ((query: Query) => boolean | "always")</code> (default: <code>true</code>)
<ul>
<li><code>true</code>로 설정할 경우 네트워크가 다시 연결되면 데이터가 오래되었을 경우 데이터를 다시 가져옵니다.</li>
<li><code>false</code>로 설정할 경우 네트워크가 다시 연결되어도 데이터를 다시 가져오지 않습니다.</li>
<li><code>always</code>로 설정할 경우 네트워크가 디시 연결되면 항상 데이터를 다시 가져옵니다.</li>
<li>함수 형태로 설정할 경우 함수의 반환 값에 따라 데이터를 다시 가져옵니다.</li>
</ul>
</li>
<li><code>notifyOnChangeProps: string[] | "all" | (() => string[] | "all")</code>
<ul>
<li>쿼리의 반환 키 값을 배열로 전달합니다. 배열로 전달 한 키의 반환 값이 변경될 경우 컴포넌트가 재렌더링됩니다. 예를 들어, <code>['data', 'error']</code>로 설정할 경우 <code>data</code> 나 <code>error</code>의 값이 변경되면 컴포넌트가 재랜더링됩니다.</li>
<li><code>all</code>로 설정할 경우 쿼리의 반환 값 중 하나라도 값이 변경될 경우 컴포넌트가 재렌더링됩니다.</li>
<li>함수 형태로 설정할 경우 함수의 반환 값에 따라 컴포넌트가 재렌더링됩니다.</li>
</ul>
</li>
<li><code>select: (data: TData) => unknown</code>
<ul>
<li><code>queryFn</code> 함수에서 반환한 값을 가공할 때 사용되는 옵션입니다. 반환된 값이 <code>data</code>에 담기지만 쿼리 캐시에는 영향을 주지 않습니다.</li>
</ul>
</li>
<li><code>initialData: TData | () => TData</code>
<ul>
<li>쿼리가 생성되거나 캐시 되지 않은 경우 이 값은 캐시 되어, 쿼리의 초기 데이터로 사용됩니다.</li>
</ul>
</li>
<li><code>initialDataUpdatedAt: number | (() => number | undefined)</code>
<ul>
<li><code>initialData</code>가 마지막으로 업데이트된 시간(ms)으로 사용됩니다.</li>
</ul>
</li>
<li><code>placeholderData: TData | (previousValue: TData | undefined; previousQuery: Query | undefined,) => TData</code>
<ul>
<li>이 값은 쿼리가 <code>pending</code> 상태일 때 placeholder로 사용할 수 있는 데이터로 사용됩니다. 이 값은 쿼리 캐시에 영향을 주지 않습니다.</li>
<li>함수로 설정할 경우 함수의 첫 번째 파라미터는 이전에 가져온 쿼리 데이터이고 두 번째 파라미터는 이전에 완료된 쿼리 인스턴스입니다. 함수의 반환 값이 placeholder 데이터로 사용됩니다.</li>
<li><code>initialData</code>와 함께 설정되어 있다면, <code>initialData</code>가 더 높은 우선순위를 가집니다.</li>
</ul>
</li>
<li><code>structuralSharing: boolean | (&#x3C;T>(oldData: T | undefined, newData: T) => T)</code> (default: <code>true</code>)
<ul>
<li><code>false</code>로 설정할 경우 쿼리가 가져온 데이터를 공유하지 않습니다.</li>
<li>함수로 설정할 경우 함수의 첫 번째 파라미터는 이전에 가져온 쿼리 데이터이고 두 번째 파라미터는 새 쿼리 데이터입니다. 이 함수는 이전 데이터의 참조를 최대한 유지하면서 새로운 데이터를 반환하는 것이 좋습니다. 함수에서 반환한 데이터가 <code>data</code>로 사용됩니다.</li>
</ul>
</li>
<li><code>throwOnError: undefined | boolean | (error: TError, query: Query) => boolean</code>
<ul>
<li><code>true</code>로 설정할 경우 쿼리에서 에러가 발생할 경우 가장 가까운 에러 바운더리(Error Boundary)로 에러를 전파합니다.</li>
<li><code>false</code>로 설정할 경우 쿼리에서 에러가 발생해도 에러 바운더리로 에러를 전파하지 않습니다.</li>
<li>함수로 설정할 경우 첫 번째 파라미터로 에러 정보 두 번째 파라미터로 쿼리 정보가 담기고 이 값들로 에러 바운더리로 보낼지(<code>true</code>) 말지(<code>false</code>)를 결정하여 반환해야 합니다.</li>
</ul>
</li>
<li><code>meta: Record&#x3C;string, unknown></code>
<ul>
<li>필요에 따라 쿼리 캐시에 저장할 수 있는 추가정보입니다. 이 값이 <code>queryFn</code>의 <code>context</code>의 <code>meta</code>에 전달됩니다.</li>
</ul>
</li>
<li><code>queryClient?: QueryClient</code>
<ul>
<li>커스텀한 쿼리 클라이언트를 지정할 수 있습니다. 이 값을 설정하지 않는다면 가장 가까운 콘텍스트의 쿼리 클라이언트가 사용됩니다.</li>
</ul>
</li>
</ul>
<blockquote>
<p><strong><code>placeholderData</code> 활용</strong></p>
<p>React Query V4에서는 <code>keepPreviousData</code> 옵션으로 쿼리 키가 변경되어 새로운 데이터를 가져오는 동안에 이전 데이터를 유지하여 화면에 노출시킬 수 있었습니다. V5부터는 <code>keepPreviousData</code> 옵션이 없어지고 아래 코드와 같이 <code>placeholderData</code> 옵션이 그 기능을 대체합니다.</p>

<h5 id="options-2">Options<a class="anchor after" aria-hidden="true" tabindex="-1" href="#options-2"><span class="anchor-icon">#</span></a></h5>
<p><code>useInfiniteQuery</code> 훅의 옵션은 <a href="/tech/react/tanstack-query-v5-api-reference/#options"><code>useQuery</code> 훅의 옵션</a>에 아래 목록의 옵션이 추가됩니다.</p>
<ul>
<li><code>queryFn: (context: QueryFunctionContext) => Promise&#x3C;TData></code> (<strong>필수</strong>, 단 <code>defaultOptions</code>에서 정의된 경우 생략 가능)
<ul>
<li><code>useQuery</code>에서 사용하는 <code>queryFn</code>와 동일하지만 <code>context.pageParam: TPageParam</code>와 <code>context.direction: 'forward' | 'backward'</code>를 추가로 사용할 수 있습니다.
<ul>
<li><code>context.pageParam: TPageParam</code>
<ul>
<li>현재 페이지(현재 <code>data</code>)를 가져오기 위해 사용된 파라미터입니다.</li>
</ul>
</li>
<li><code>context.direction: 'forward' | 'backward'</code>
<ul>
<li>현재 페이지를 가져올 방향입니다.</li>
</ul>
</li>
</ul>
</li>
</ul>
</li>
<li><code>initialPageParam: TPageParam</code> (<strong>필수</strong>)
<ul>
<li>첫 페이지를 가져올 때 사용할 파라미터입니다.</li>
</ul>
</li>
<li><code>getNextPageParam: (lastPage, allPages, lastPageParam, allPageParams) => TPageParam | undefined | null</code> (<strong>필수</strong>)
<ul>
<li>최근 페이지(<code>lastPage</code>), 모든 페이지(<code>allPages</code>), 최근 파마리터(<code>lastPageParam</code>), 모든 파라미터(<code>allPageParams</code>) 이 데이터를 사용하여 다음 페이지를 가져오는 데 사용되는 파라미터를 반환해야 하는 함수입니다.</li>
<li><code>undefined</code>나 <code>null</code>을 반환할 경우 다음 페이지가 없는 것으로 판단합니다.</li>
</ul>
</li>
<li><code>getPreviousPageParam: (firstPage, allPages, firstPageParam, allPageParams) => TPageParam | undefined | null</code>
<ul>
<li>최근 페이지(<code>firstPage</code>), 모든 페이지(<code>allPages</code>), 첫 파마리터(<code>firstPageParam</code>), 모든 파라미터(<code>allPageParams</code>) 이 데이터를 사용하여 이전 페이지를 가져오는 데 사용되는 파라미터를 반환해야 하는 함수입니다.</li>
<li><code>undefined</code>나 <code>null</code>을 반환할 경우 이전 페이지가 없는 것으로 판단합니다.</li>
</ul>
</li>
<li><code>maxPages: number | undefined</code> (default: <code>undefined</code>)
<ul>
<li><code>data</code> 반환 값에 저장할 최대 페이지 수입니다.</li>
<li>최대 페이지 수에 도달하면 방향에 따라 첫 번째 또는 마지막 페이지가 제거됩니다.</li>
<li><code>undefined</code>나 <code>0</code>이 설정된 경우 저장할 수 있는 페이지 수의 제한이 없게 됩니다.</li>
</ul>
</li>
</ul>

</ul>
</li>
<li><code>isFetchingPreviousPage: boolean</code>
<ul>
<li><code>fetchPreviousPage</code> 함수로 이전 페이지를 가져오는 동안 <code>true</code>입니다.</li>

<ul>
<li><code>true</code>로 설정할 경우 쿼리가 데이터를 가져오는 중일 경우 진행 중이던 요청을 취소하고 재요청합니다.</li>
<li><code>false</code>로 설정할 경우 쿼리가 데이터를 가져오는 중일 경우 데이터를 재요청하지 않습니다.</li>

</li>
</ul>

</li>

</li>

<ul>
<li>낙관적 업데이트란 mutation이 성공할 것이라 판단하여 수정된 결과를 응답받기 전, 요청한 데이터를 사용하여 업데이트하는 것을 말합니다.</li>
</ul>
</li>
</ul>

</ul>

<li><code>false</code>로 설정할 경우 신선한(fresh) 쿼리 중에 찾습니다.</li>
</ul>
</li>
<li><code>filters.fetchStatus?: 'fetching' | 'paused' | 'idle'</code>
<ul>
<li><code>fetching</code>으로 설정할 경우 가져오는 중인 쿼리 중에 찾습니다.</li>
<li><code>paused</code>로 설정할 경우 데이터를 가져오려고 했지만 일시 중단된 쿼리 중에 찾습니다.</li>
<li><code>idle</code>로 설정할 경우 데이터를 가져온 적이 없는 쿼리 중에 찾습니다.</li>
</ul>
</li>
<li><code>filters.predicate?: (query: Query) => boolean</code>
<ul>
<li>최종 필터로 사용되는 함수입니다. 다른 필터를 정의하지 않으면 모든 쿼리 중에 찾습니다.</li>
</ul>
</li>
</ul>
</li>
<li><code>queryClient?: QueryClient</code>
<ul>
<li>커스텀한 쿼리 클라이언트를 지정할 수 있습니다. 이 값을 설정하지 않는다면 가장 가까운 콘텍스트의 쿼리 클라이언트가 사용됩니다.</li>
</ul>
</li>
</ul>

<p><code>QueryCache</code>의 옵션들은 모두 콜백함수입니다. 전역에서 처리해야 할 적업을 할 때 사용할 수 있습니다.</p>
<ul>
<li><code>onError?: (error: unknown, query: Query) => void</code>
<ul>
<li>실행한 쿼리에 에러가 발생할 경우 호출되는 콜백함수입니다.</li>
<li><code>error: unknown</code>
<ul>
<li>발생한 에러 정보가 담긴 객체입니다.</li>
</ul>
</li>
<li><code>query: Query</code>
<ul>
<li>실행한 쿼리 객체입니다.</li>
</ul>
</li>
</ul>
</li>
<li><code>onSuccess?: (data: unknown, query: Query) => void</code>
<ul>
<li>실행한 쿼리가 성공하면 호출되는 콜백함수입니다.</li>
<li><code>data: unknown</code>
<ul>
<li><code>queryFn</code> 함수의 반환 값입니다.</li>
</ul>
</li>
<li><code>query: Query</code>
<ul>
<li>실행한 쿼리 객체입니다.</li>
</ul>
</li>
</ul>
</li>
<li><code>onSettled?: (data: unknown | undefined, error: unknown | null, query: Query) => void</code>
<ul>
<li>실행한 쿼리가 성공 혹은 실패하여 종료되면 호출되는 콜백함수입니다.</li>
<li><code>data: unknown | undefined</code>
<ul>
<li>쿼리가 성공한 경우 <code>queryFn</code> 함수의 반환 값입니다.</li>
</ul>
</li>
<li><code>error: unknown | null</code>
<ul>
<li>쿼리가 실패한 경우 발생한 에러 정보가 담긴 객체입니다.</li>
</ul>
</li>
<li><code>query: Query</code>
<ul>
<li>실행한 쿼리 객체입니다.</li>
</ul>
</li>
</ul>
</li>
</ul>
<blockquote>
<p><strong><code>QueryClient</code>의 <code>defaultOptions</code>와 <code>QueryCache</code>의 옵션의 차이</strong></p>
<ul>
<li><code>defaultOpions</code>의 콜백함수들은 각각의 쿼리를 호출할 때 오버라이드될 수 있습니다. <code>QueryCache</code>의 전역 콜백함수들은 항상 호출됩니다.</li>
<li><code>defaultOpions</code>의 콜백함수들은 각각의 옵저버에서 한 번씩 호출되지만, <code>QueryCache</code>의 전역 콜백함수들은 한 번만 호출됩니다.
<ul>
<li>예를 들어 <code>useQuery({ queryKey: ['posts'] })</code>와 같이 동일한 쿼리가 부모, 자식 컴포넌트 각각에 2번 선언되었다면 <code>defaultOpions</code>의 콜백함수는 2번 호출되지만, <code>QueryCache</code>의 전역 콜백함수는 한 번만 호출됩니다.</li>
</ul>
</li>
</ul>
</blockquote>

<ul>
<li><code>true</code>로 설정할 경우 오래된(stale) 쿼리 중에 찾습니다.</li>
<li><code>false</code>로 설정할 경우 신선한(fresh) 쿼리 중에 찾습니다.</li>
</ul>
</li>
<li><code>filters.fetchStatus?: 'fetching | 'paused' | 'idle'</code>
<ul>
<li><code>fetching</code>으로 설정할 경우 가져오는 중인 쿼리 중에 찾습니다.</li>
<li><code>paused</code>로 설정할 경우 데이터를 가져오려고 했지만 일시 중단된 쿼리 중에 찾습니다.</li>
<li><code>idle</code>로 설정할 경우 데이터를 가져온 적이 없는 쿼리 중에 찾습니다.</li>
</ul>
</li>
<li><code>filters.predicate?: (query: Query) => boolean</code>
<ul>
<li>최종 필터로 사용되는 함수입니다. 다른 필터를 정의하지 않으면 모든 쿼리 중에 찾습니다.</li>
</ul>
</li>
</ul>
</li>
</ul>
</li>
<li><code>findAll: (filters: QueryFilters) => Query[]</code>
<ul>
<li><code>filters</code>에 해당하는 쿼리를 배열 형태로 반환하는 함수입니다. 해당하는 쿼리가 없을 경우 `빈 배열을 반환합니다.</li>
<li><code>find</code> 함수의 <code>filters</code>와 동일한 값을 파라미터로 전달받습니다.</li>
</ul>
</li>
<li><code>subscribe: (callback: (event: QueryCacheNotifyEvent) => void) => unsubscribe: Function => void</code>
<ul>
<li>쿼리 캐시를 구독합니다. <code>query.setState</code>나 <code>queryClient.removeQueries</code> 등 쿼리가 업데이트될 때마다 업데이트된 쿼리를 파라미터로 하여 <code>callback</code> 함수가 호출됩니다.</li>
<li>구독을 취소하는 함수인 <code>unsubscribe</code>를 반환합니다.</li>
<li>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="tsx"><code><span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">const</span><span style="color:#622CBC;--shiki-dark:#DBB7FF"> callback</span><span style="color:#A0111F;--shiki-dark:#FF9492"> =</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> (</span><span style="color:#702C00;--shiki-dark:#FFB757">event</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">) </span><span style="color:#A0111F;--shiki-dark:#FF9492">=></span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> {</span></span>

</li>

<h5 id="options-7">Options<a class="anchor after" aria-hidden="true" tabindex="-1" href="#options-7"><span class="anchor-icon">#</span></a></h5>
<p><code>MutationCache</code>의 옵션들은 모두 콜백함수입니다. 전역에서 처리해야 할 적업을 할 때 사용할 수 있습니다.</p>
<ul>
<li><code>onError?: (error: unknown, variables: unknown, context: unknown, mutation: Mutation) => Promise&#x3C;unknown> | unknown</code>
<ul>
<li>실행한 Mutation에 에러가 발생할 경우 호출되는 콜백함수입니다. <code>Promise</code>를 반환할 경우 <code>resolved</code> 될 때까지 이후 작업들이 진행되지 않습니다.</li>
<li><code>error: unknown</code>
<ul>
<li>발생한 에러 정보가 담긴 객체입니다.</li>
</ul>
</li>
<li><code>variables: unknown</code>
<ul>
<li><code>mutate</code>(또는 <code>mutateAsync</code>) 함수의 <code>variables</code> 파라미터로 전달한 값입니다.</li>
</ul>
</li>
<li><code>context: unknown</code>
<ul>
<li><code>useMutation</code> 훅의 옵션 중 <code>onMutate</code> 함수의 반환 값입니다.</li>
</ul>
</li>
<li><code>mutation: Mutation</code>
<ul>
<li>실행한 Mutation 객체입니다.</li>
</ul>
</li>
</ul>
</li>
<li><code>onSuccess?: (data: unknown, variables: unknown, context: unknown, mutation: Mutation) => Promise&#x3C;unknown> | unknown</code>
<ul>
<li>실행한 Mutation이 성공하면 호출되는 콜백함수입니다. <code>Promise</code>를 반환할 경우 <code>resolved</code> 될 때까지 이후 작업들이 진행되지 않습니다.</li>
<li><code>data: unknown</code>
<ul>
<li><code>mutationFn</code> 함수의 반환 값입니다.</li>
</ul>
</li>
<li><code>variables: unknown</code>
<ul>
<li><code>mutate</code>(또는 <code>mutateAsync</code>) 함수의 <code>variables</code> 파라미터로 전달한 값입니다.</li>
</ul>
</li>
<li><code>context: unknown</code>
<ul>
<li><code>useMutation</code> 훅의 옵션 중 <code>onMutate</code> 함수의 반환 값입니다.</li>
</ul>
</li>
<li><code>mutation: Mutation</code>
<ul>
<li>실행한 Mutation 객체입니다.</li>
</ul>
</li>
</ul>
</li>
<li><code>onSettled?: (data: unknown | undefined, error: unknown | null, variables: unknown, context: unknown, mutation: Mutation) => Promise&#x3C;unknown> | unknown</code>
<ul>
<li>실행한 Mutation이 성공 혹은 실패하여 종료되면 호출되는 콜백함수입니다. <code>Promise</code>를 반환할 경우 <code>resolved</code> 될 때까지 이후 작업들이 진행되지 않습니다.</li>
<li><code>data: unknown | undefined</code>
<ul>
<li>Mutation이 성공한 경우 <code>mutationFn</code> 함수의 반환 값입니다.</li>
</ul>
</li>
<li><code>error: unknown | null</code>
<ul>
<li>Mutation이 실패한 경우 발생한 에러 정보가 담긴 객체입니다.</li>
</ul>
</li>
<li><code>variables: unknown</code>
<ul>
<li><code>mutate</code>(또는 <code>mutateAsync</code>) 함수의 <code>variables</code> 파라미터로 전달한 값입니다.</li>
</ul>
</li>
<li><code>context: unknown</code>
<ul>
<li><code>useMutation</code> 훅의 옵션 중 <code>onMutate</code> 함수의 반환 값입니다.</li>
</ul>
</li>
<li><code>mutation: Mutation</code>
<ul>
<li>실행한 Mutation 객체입니다.</li>
</ul>
</li>
</ul>
</li>
<li><code>onMutate?: (variables: unknown, mutation: Mutation) => Promise&#x3C;unknown> | unknown</code>
<ul>
<li>Mutation이 실행되기 전에 호출되는 콜백합수입니다.</li>
<li><code>variables: unknown</code>
<ul>
<li><code>mutate</code>(또는 <code>mutateAsync</code>) 함수의 <code>variables</code> 파라미터로 전달한 값입니다.</li>
</ul>
</li>
<li><code>mutation: Mutation</code>
<ul>
<li>실행한 Mutation 객체입니다.</li>
</ul>
</li>
</ul>
</li>
</ul>

<li><code>defaultOpions</code>에 정의한 콜백함수들은 각각의 Mutation을 호출할 때 오버라이드될 수 있습니다. <code>MutationCache</code>에 정의한 전역 콜백함수들은 항상 호출됩니다.</li>
