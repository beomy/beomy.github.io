<li><code>import { setContext } from 'svelte'</code>로 <code>setContext</code>를 가져오고 <code>import { key } from './mapbox.js'</code>로 <code>key</code>를 가져옵니다. 여기서 가져온 <code>setContext</code>와 <code>key</code>는 공유하는 데이터를 생성하는데 사용됩니다.</li>
</ul>
<p><code>setContext</code>로 공유하는 데이터를 Context라고 합니다. Context는 라이프 사이클 메서드는 물론 어떤 값이든 가능합니다.</p>
<p><code>setContext</code>와 <code>getContext</code>는 컴포넌트가 초기화될 때 호출되어야 합니다. 컴포넌트가 초기화될 때의 <code>map</code> 변수는 아직 정의되어 있지 않은 상태입니다. <code>map</code> 변수는 컴포넌트가 마운트 된 후 정의되기 때문에, <code>setContext</code>로 만들어진 Context는 <code>map</code> 변수가 아닌 <code>map</code> 변수를 리턴하는 함수여야 다른 컴포넌트에서 <code>map</code> 변수를 가져올 수 있게 됩니다.</p>

<li><code>getMap</code> 함수로 <code>map</code> 객체를 가져옵니다. <code>map</code> 객체는 <code>Map</code> 컴포넌트에서 <code>setContext</code>를 사용하여 공유한 객체입니다.</li>
<li><code>mapbox.Popup</code>와 <code>mapbox.Marker</code>를 사용하여 지도에 마크를 표시합니다.</li>
</ul>
<p><code>setContext</code>로 Context를 만들 때 사용한 <code>key</code>을 사용하여 Context를 가져올 수 있습니다. <code>mapbox.js</code>의 <code>key</code>를 사용하여 <code>setContext</code>로 만든 Context를 <code>getContext</code>를 사용하여 가져옵니다.</p>
<h3 id="mapboxjs"><code>mapbox.js</code><a class="anchor after" aria-hidden="true" tabindex="-1" href="#mapboxjs"><span class="anchor-icon">#</span></a></h3>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="js"><code><span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">// mapbox.js</span></span>

<li><code>key</code>를 통해 생성한 <code>map</code> 객체를 공유합니다.</li>
</ul>
<p><code>setContext</code>, <code>getContext</code>에 사용되는 <code>key</code>는 어떤 값이든 사용할 수 있습니다. <code>'x' === 'x'</code>이지만 <code>{} !== {}</code> 이기 때문에 유니크한 <code>key</code>를 만들기 위해 예제에서 <code>key</code>로 빈 객체를 사용하였습니다.</p>
<p><code>key</code>를 문자열을 사용하면 다른 Context와 충돌할 가능성이 있지만, 객체를 사용하여 다른 Context와 충돌을 피할 수 있습니다.</p>
<h2 id="context-vs-store">Context VS Store<a class="anchor after" aria-hidden="true" tabindex="-1" href="#context-vs-store"><span class="anchor-icon">#</span></a></h2>
<p>Context와 Store은 비슷합니다. Store는 애플리케이션의 어느 위치에서나 사용할 수 있지만 Context는 해당 컴포넌트와 하위 컴포넌트에서만 사용할 수 있다는 차이가 있습니다.</p>
<p>이러한 특징은 하나의 컴포넌트로 여러 인스턴스를 생성하게 될 때 각각의 인스턴스가 하나의 상태를 공유하지 않고 각각의 상태를 가질 수 있는 장점이 있습니다.</p>
<p>Context는 반응형으로 동작하지 않기 때문에 변경되어 반응형으로 동작해야 할 경우 Store을 사용해야 합니다.</p>
