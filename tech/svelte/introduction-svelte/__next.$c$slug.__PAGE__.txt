<h4 id="번들-크기-감소">번들 크기 감소<a class="anchor after" aria-hidden="true" tabindex="-1" href="#번들-크기-감소"><span class="anchor-icon">#</span></a></h4>

<p>SPA의 전형적인 단점은 첫 로딩 시 사용되는 모든 리소스를 다운로드하고, 파싱하고, 실행되기 때문에 첫 로딩에 많은 시간이 걸린다는 것입니다. 번들 크기가 줄어들면, 그만큼 다운로드해야 할 리소스가 줄고, 파싱 할 양이 줄기 때문에 첫 로딩 속도가 개선됩니다.</p>
<h4 id="유지-보수-비용-감소">유지 보수 비용 감소<a class="anchor after" aria-hidden="true" tabindex="-1" href="#유지-보수-비용-감소"><span class="anchor-icon">#</span></a></h4>
<p>코드 양이 줄어들면 유지 보수에 사용되는 비용이 감소합니다. 프로젝트 개발 시간과 버그의 개수는 코드 양에 따라 선형적으로 증가하는 것이 아니라 2차식으로 증가한다고 합니다(<a href="https://svelte.dev/blog/write-less-code">https://svelte.dev/blog/write-less-code</a> 참고함). 코드를 유지 보수하는 입장에서도 코드를 읽고 이해하는데 코드 양이 적으면 좀 더 빠르고 쉽게 이해할 수 있습니다.</p>
<h3 id="no-virtual-dom">No Virtual DOM<a class="anchor after" aria-hidden="true" tabindex="-1" href="#no-virtual-dom"><span class="anchor-icon">#</span></a></h3>
<p>Vue.js와 React는 가상돔을 사용합니다. Vue.js와 React는 가상돔이 빠르다는 인식을 프론트엔드 개발자들에게 심어주었습니다. 물론 가상돔은 대부분의 경우 실제돔(Real DOM)보다 빠릅니다.</p>
<h4 id="가상돔은-항상-빠르지-않습니다">가상돔은 항상 빠르지 않습니다.<a class="anchor after" aria-hidden="true" tabindex="-1" href="#가상돔은-항상-빠르지-않습니다"><span class="anchor-icon">#</span></a></h4>
<p>하지만 가상돔을 사용하는 것이 항상 빠른 것은 아닙니다. 가상돔이 변경되면, 새로운 가상돔과 변경되기 전의 가상돔을 비교하여 변경된 내용을 실제돔에 적용을 하는데, 이때 가상돔을 비교하는 오버헤드가 발생합니다. 오버헤드가 발생하지 않는다면 React에서 <code>shouldComponentUpdate</code>를 사용하여 최적화하는 방법은 필요 없을 것입니다.</p>
<h4 id="런타임-프레임워크를-포함하지-않습니다">런타임 프레임워크를 포함하지 않습니다.<a class="anchor after" aria-hidden="true" tabindex="-1" href="#런타임-프레임워크를-포함하지-않습니다"><span class="anchor-icon">#</span></a></h4>
<p>Svelte는 가상돔을 사용하지 않습니다. 가상돔은 변경된 내용을 알기 위한 수단으로 사용됩니다. Svelte는 가상돔을 사용하지 않아도 변경된 내용을 알 수 있는 다른 수단을 사용하기 때문에 가상돔을 사용하지 않습니다.</p>
<p>가상돔을 사용하지 않아서 번들에는 변경된 내용을 알기 위해 사용되는 런타임 프레임워크가 포함되지 않습니다. 런타임 프레임워크를 포함하지 않기 때문에 번들 크기가 더 작아지게 됩니다.</p>
<h3 id="truly-reactive">Truly reactive<a class="anchor after" aria-hidden="true" tabindex="-1" href="#truly-reactive"><span class="anchor-icon">#</span></a></h3>
<p>Vue.js와 React는 런타임에 가상돔을 비교하여 변경된 내용을 파악하는 방식을 사용합니다. 반면에 Svelte는 빌드 타임(Build Time)에 어느 부분이 변경될지 파악하는 방식을 사용합니다. Svelte는 어느 부분이 변경될지 파악하고 그 부분의 상태(state)가 변경될 경우 반응형으로 화면을 갱신하는 진짜 반응형입니다.</p>
<h4 id="svelte는-컴파일러입니다">Svelte는 컴파일러입니다.<a class="anchor after" aria-hidden="true" tabindex="-1" href="#svelte는-컴파일러입니다"><span class="anchor-icon">#</span></a></h4>
<p>Svelte는 공식 문서에는 컴파일러라고 소개합니다. <a href="https://ko.wikipedia.org/wiki/%EC%BB%B4%ED%8C%8C%EC%9D%BC%EB%9F%AC">위키백과</a>에서</p>
<blockquote>
<p>컴파일러는 특정 프로그래밍 언어로 쓰여 있는 문서를 다른 프로그래밍 언어로 옮기는 프로그램을 말한다.</p>
</blockquote>
<p>라고 정의하고 있습니다. Svelte는 빌드 타임에 돔을 업데이트하는 효율적인 명령 코드로 변환하기 때문에 컴파일러라고 소개하는 것으로 생각됩니다.</p>
<h2 id="svelte-사용-시-유의사항">Svelte 사용 시 유의사항<a class="anchor after" aria-hidden="true" tabindex="-1" href="#svelte-사용-시-유의사항"><span class="anchor-icon">#</span></a></h2>
<p>Svelte를 프로젝트에 도입하기 전에 고려해야 할 몇 가지 사항들에 대해 이야기해보도록 하겠습니다.</p>
<h3 id="cdn으로-svelte-사용-불가능합니다">CDN으로 Svelte 사용 불가능합니다.<a class="anchor after" aria-hidden="true" tabindex="-1" href="#cdn으로-svelte-사용-불가능합니다"><span class="anchor-icon">#</span></a></h3>
<p>Svelte는 앞에서 이야기 한 것처럼 빌드 타임에 반응형이 결정됩니다. 빌드 타임에 결정되기 때문에 런타임에 오버헤드를 줄여 성능을 향상시킬 수 있는 장점이 있지만, 런타임 프레임워크를 포함하고 있지 않기 때문에 CDN 등으로 Svelte를 사용할 수 없습니다.</p>
<h3 id="브라우저-지원-체크가-필요합니다">브라우저 지원 체크가 필요합니다.<a class="anchor after" aria-hidden="true" tabindex="-1" href="#브라우저-지원-체크가-필요합니다"><span class="anchor-icon">#</span></a></h3>
<p>공식 문서에서 정식으로 어느 브라우저까지 지원한다고 이야기하고 있지 않습니다. IE11 이하의 구형 브라우저에서 Svelte를 사용하기 위해서는 별도의 설정 작업이 필요합니다.</p>
<p>참고: <a href="https://github.com/sveltejs/svelte/issues/558">Github</a>에 Svelte에 브라우저 지원 이슈가 올라와 있습니다.</p>
<h3 id="svelte-생태계를-생각해야-합니다">Svelte 생태계를 생각해야 합니다.<a class="anchor after" aria-hidden="true" tabindex="-1" href="#svelte-생태계를-생각해야-합니다"><span class="anchor-icon">#</span></a></h3>
<p>Svelte는 신규 프레임워크인 만큼 지금은 Vue.js나 React 만큼 생태계가 크지 않습니다. state 관리는 별도의 라이브러리가 아닌 Svelte에서 정식으로 지원합니다.</p>
<h4 id="cli-라이브러리">CLI 라이브러리<a class="anchor after" aria-hidden="true" tabindex="-1" href="#cli-라이브러리"><span class="anchor-icon">#</span></a></h4>
<p>React의 <code>create-react-app</code>이나 Vue.js의 <code>vue-cli</code>와 같이 간편하게 프로젝트를 생성할 수 있는 CLI 라이브러리가 아직 존재하지 않습니다. 다만, Github에 <a href="https://github.com/sveltejs/template"><code>rollup</code></a>, <a href="https://github.com/sveltejs/template-webpack"><code>webpack</code></a> 두 가지 버전의 보일러 플레이트(boilerplate)가 올라와 있어 클론으로 프로젝트를 간단히 생성할 수 있습니다.</p>
<h4 id="router-라이브러리">router 라이브러리<a class="anchor after" aria-hidden="true" tabindex="-1" href="#router-라이브러리"><span class="anchor-icon">#</span></a></h4>
<p>Svelte에서 공식으로 제공하는 router 라이브러리가 없습니다. (<code>svelte-spa-router</code>가 많이 사용되는 router 라이브러리로 보입니다.)</p>
<h2 id="요약">요약<a class="anchor after" aria-hidden="true" tabindex="-1" href="#요약"><span class="anchor-icon">#</span></a></h2>
<h4 id="svelte의-특징-및-장점">Svelte의 특징 및 장점<a class="anchor after" aria-hidden="true" tabindex="-1" href="#svelte의-특징-및-장점"><span class="anchor-icon">#</span></a></h4>
<ul>
<li>코드를 간결하게 작성할 수 있습니다.</li>
<li>가상돔을 사용하지 않습니다.
<ul>
<li>변경된 위치를 정확하게 알아 돔을 비교하는 런타임 프레임워크가 필요 없습니다.</li>
<li>돔을 비교하는데 드는 오버헤드가 없습니다.</li>
<li>돔을 비교하는 런타임 프레임워크가 없어 번들의 크기가 작습니다.</li>
</ul>
</li>
<li>진짜 반응형 프레임워크입니다.
<ul>
<li>변경된 위치를 찾아 변경하는 것이 아니라, 변경된 위치를 정확하게 아는 진짜 반응형입니다.</li>
</ul>
</li>
</ul>
<h4 id="svelte-사용-시-유의사항-1">Svelte 사용 시 유의사항<a class="anchor after" aria-hidden="true" tabindex="-1" href="#svelte-사용-시-유의사항-1"><span class="anchor-icon">#</span></a></h4>
<ul>
<li>CDN으로 svelte를 사용할 수 없습니다.</li>
<li>구형 브라우저에서 동작하는지 확인해 보아야 합니다.</li>
<li>신규 프레임워크이기 때문에 생태계가 아직 크지 않습니다.</li>
</ul>
