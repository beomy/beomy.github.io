<p>Vue.js 코드에서 <code>&#x3C;li></code> 태그에 <code>:key="..."</code> 속성이 있는 것을 볼 수 있습니다. <code>key</code> 속성은 <code>v-for</code>의 리스트에서 변경된 위치를 정확히 찾아 DOM에 변경된 부분만 적용하기 위해 사용됩니다.</p>
<p>Svelte에서도 Vue.js의 <code>key</code> 속성과 동일한 역할을 하는 코드가 있습니다. 그 부분은 위의 코드에서 <code>(id)</code>로 작성된 부분입니다. 괄호(<code>(...)</code>) 안에 중복되지 않는 유니크한 키 값을 정의하여 변경된 부분만 정확히 DOM에 반영할 수 있게 됩니다.</p>
<h3 id="key의-특징">key의 특징<a class="anchor after" aria-hidden="true" tabindex="-1" href="#key의-특징"><span class="anchor-icon">#</span></a></h3>
<p>Svelte는 반복문 블록에 내부적으로 <a href="https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Global_Objects/Map"><code>Map</code></a>을 사용하기 때문에 key에 숫자나 문자열뿐만 아니라 객체가 정의될 수도 있습니다. 하지만 key는 숫자나 문자열이 오는 것이 더 안전합니다. 그 이유는, 예를 들어 API 서버에게 응답받은 리스트를 화면에 그려야 한다면 그 과정은 아래와 같을 것입니다.</p>
<ol>
<li>API 서버의 API를 호출하여 결과 값은 기다린다.</li>
<li>API 서버로부터 결과 값을 응답받는다.</li>
<li>API 서버에게 받은 결과 값을 변수에 저장한다.</li>
<li>저장한 변수를 반복문 블록으로 화면에 나타낸다.</li>
</ol>
<p>API를 다시 호출해서 위의 4가지 과정을 다시 거치게 되더라도 서버에게 응답받은 결과 값은 동일하기 때문에 화면의 변화는 없을 것입니다. 하지만 key를 객체로 정의하였다면 객체가 동일한 값을 가지는 객체라도 서로 다른 객체이기 때문에 화면 전체를 다시 그리게 됩니다. 이런 이유로 key는 객체보다는 API 응답 값 중의 유니크한 id가 되는 것이 더 좋습니다.</p>
<h2 id="await-블록">await 블록<a class="anchor after" aria-hidden="true" tabindex="-1" href="#await-블록"><span class="anchor-icon">#</span></a></h2>
<p>많은 웹 애플리케이션은 비동기 데이터 처리를 합니다. Svelte는 HTML 안에서 직접 비동기 데이터 처리를 할 수 있습니다.</p>

<ul>
<li><code>{#awit promise}</code>와 <code>{:then number}</code> 사이: 비동기 작업이 응답하기 전에 화면에 노출되는 블록입니다.</li>
<li><code>{:then number}</code>와 <code>{:catch error}</code> 사이: 비동기 작업이 응답하여 응답된 결과가 화면에 노출되는 블록입니다.</li>
<li><code>{:catch error}</code>와 <code>{/await}</code> 사이: 비동기 작업에서 에러가 발생할 경우 에러 값이 화면에 노출되는 블록입니다.</li>
</ul>
<p>비동기 작업에 에러(혹은 <code>reject</code>)가 발생하지 않는 것을 확신할 수 있다면 <code>catch</code> 블록을 생략할 수 있습니다. <code>catch</code> 블록을 생략한 코드는 아래와 같습니다.</p>
