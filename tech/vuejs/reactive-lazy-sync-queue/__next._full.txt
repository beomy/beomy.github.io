<code>src/core/instance/state.js</code> 파일은 <a href="/tech/vuejs/initialize-mixin-layer/">3. Initialize - Mixin Layer</a>와 <a href="/tech/vuejs/initialize-_init-function/">4. Initialize - _init 함수</a>에서 살펴보았던 파일입니다.</p>
<p><code>evaluate</code> 함수는 <code>src/core/instance/state.js</code> 파일의 <code>createComputedGetter</code> 함수에서 사용 됩니다.</p>

<h3 id="queue">Queue<a class="anchor after" aria-hidden="true" tabindex="-1" href="#queue"><span class="anchor-icon">#</span></a></h3>
<p>lazy, sync 모드가 아닐 경우, queue 모드로 동작합니다. queue 모드에서 <code>update</code> 함수에서 <code>queueWatcher(this)</code>를 실행합니다.</p>

<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">  const</span><span style="color:#023B95;--shiki-dark:#91CBFF"> id</span><span style="color:#A0111F;--shiki-dark:#FF9492"> =</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> watcher.id</span></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">  if</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> (has[id] </span><span style="color:#A0111F;--shiki-dark:#FF9492">==</span><span style="color:#023B95;--shiki-dark:#91CBFF"> null</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">) {</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">    has[id] </span><span style="color:#A0111F;--shiki-dark:#FF9492">=</span><span style="color:#023B95;--shiki-dark:#91CBFF"> true</span></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">    if</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> (</span><span style="color:#A0111F;--shiki-dark:#FF9492">!</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">flushing) {</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">      queue.</span><span style="color:#622CBC;--shiki-dark:#DBB7FF">push</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(watcher)</span></span>

<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">      // if already past its id, it will be run next immediately.</span></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">      let</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> i </span><span style="color:#A0111F;--shiki-dark:#FF9492">=</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> queue.</span><span style="color:#023B95;--shiki-dark:#91CBFF">length</span><span style="color:#A0111F;--shiki-dark:#FF9492"> -</span><span style="color:#023B95;--shiki-dark:#91CBFF"> 1</span></span>

<p><code>flushing</code>이 <code>false</code>일 경우, 간단한 <code>push</code> 메소드를 호출합니다. <code>flushing</code>이 <code>true</code>일 경우 <code>watcher.id</code>의 바로 오른쪽에 <code>splice</code>를 이용하여 삽입 됩니다. 이렇게 하여, 바로 다음에 호출되도록 합니다. (queue가 flush 되고 있다는 것은 queue안에 있는 watcher들이 동작하고 있는 상태라고 이해 할 수 있을 것 같습니다.)</p>
<p>마지막으로 <code>waiting</code>이 <code>false</code>일 때, <code>nextTick</code>에 <code>flushSchedulerQueue</code>를 호출합니다.</p>
<p>Vue를 사용하면서 <code>nextTick</code>이라는 함수를 보셨을 것입니다. Vue는 매 Tick 마다 view의 변경 사항을 DOM에 그립니다. <code>nextTick</code> 함수는 다음 tick에 파라미터로 넘겨준 콜백함수를 호출됩니다.</p>
<p><code>queueWatcher</code> 함수를 보면 2개의 flag(<code>flushing</code>, <code>waiting</code>)를 사용하는 것을 볼 수 있습니다. 2개의 flag를 사용하는 이유는, <code>nextTick</code> 함수로 인해 <code>flushSchedulerQueue</code> 함수가 즉시 실행 되지 않고 다음 tick에 실행되게 됩니다. 한 tick에 <code>queueWatcher</code> 함수가 여러번 호출되면, 다음 tick에 동시에 <code>flushSchedulerQueue</code>가 여러번 호출됩니다. 한번의 tick에 한번의 <code>flushSchedulerQueue</code>를 호출하기 위해 <code>waiting</code> flag를 사용합니다.</p>
<p>즉, <code>flushing</code> flag는 queue에 있는 watcher가 동작하고 있는 것을 나타내는 flag이고, <code>waiting</code> flag를 한번의 tick에 한번의 <code>flushSchedulerQueue</code>를 호출하기 위해 사용됩니다.</p>
<h2 id="view-업데이트를-트리거하는-방법">View 업데이트를 트리거하는 방법<a class="anchor after" aria-hidden="true" tabindex="-1" href="#view-업데이트를-트리거하는-방법"><span class="anchor-icon">#</span></a></h2>
<p>watcher가 value를 업데이트 하는 것을 살펴 보았습니다. 이제까지 살펴본 watcher는 <code>computed</code> 프로퍼티와 <code>watch</code>의 콜백함수를 호출하는데 사용되었습니다.</p>
<p>view를 업데이트 하는데 watcher가 사용될 것 같은데, 지금까지 살펴본 코드 어디에서도 view를 업데이트 하는 부분이 등장하지 않았습니다. view를 업데이트 하는 코드를 찾을 수 있는 단서는 <a href="/tech/vuejs/initialize-mixin-layer/#lifecyclemixin-%ED%95%A8%EC%88%98">3. Initialize - Mixin Layer</a>에서 살펴본 <code>_update</code> 함수입니다. <code>_update</code> 함수는 DOM을 업데이트하는 역할을 합니다. <code>_update</code>를 프로젝트 전체 검색으로 어디서 사용되는지 찾아보도록 하겠습니다.</p>

<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  computed: {</span></span>
<span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">    newName</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> () {</span></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">      return</span><span style="color:#023B95;--shiki-dark:#91CBFF"> this</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">.name </span><span style="color:#A0111F;--shiki-dark:#FF9492">+</span><span style="color:#032563;--shiki-dark:#ADDCFF"> 'new!'</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">    }</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  }</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">})</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">&#x3C;/</span><span style="color:#024C1A;--shiki-dark:#72F088">script</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">></span></span></code></pre>
<p>위의 코드를 살펴보면, 하나의 <code>data</code> 프로퍼티(<code>name</code>), 하나의 <code>computed</code> 프로퍼티(<code>newName</code>)이 있고, <code>computed</code> 프로퍼티를 view에 나타내는 예제입니다.</p>
<p>위의 코드가 초기화 되면, 하나의 반응형 프로퍼티(<code>data</code>)와 그것을 구독(subscribe)하는 2개의 watcher(<code>computed</code>, view)가 생성됩니다. (<code>computed</code> 프로퍼티는 반응형 프로퍼티가 아닌 watcher이기 때문에 view는 <code>data</code> 프로퍼티를 구독합니다.)</p>
<p><code>name</code>이 변경되면, <code>computed</code> 프로퍼티와 view가 모두 업데이트 되어야 합니다. 여기서 업데이트 순서가 중요한데, view를 업데이트 하고 <code>computed</code> 프로퍼티를 업데이트 하는 순서라면 view는 이전의 <code>computed</code> 프로퍼티의 값을 그리게 됩니다.</p>
<p><code>name</code>이 변경되면, <code>dep.notify()</code>가 호출되고, <code>notify</code> 함수는 watcher의 <code>update()</code>를 호출하여 값을 업데이트 합니다. <code>lazy</code>와 <code>sync</code>의 기본 값은 모두 <code>false</code>이기 때문에 <code>queueWatcher(this)</code>가 호출 되고, 마지막으로 <code>nextTick(flushSchedulerQueue)</code>가 호출됩니다. 업데이트 순서를 살펴보기 위해 <code>flushSchedulerQueue</code>를 살펴보도록 하겠습니다.</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="js"><code><span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">/**</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC"> * Flush both queues and run the watchers.</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC"> */</span></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">function</span><span style="color:#622CBC;--shiki-dark:#DBB7FF"> flushSchedulerQueue</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> () {</span></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">  ...</span></span>
<span class="line"></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  // Sort queue before flush.</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  // This ensures that:</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  // 1. Components are updated from parent to child. (because parent is always</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  //    created before the child)</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  // 2. A component's user watchers are run before its render watcher (because</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  //    user watchers are created before the render watcher)</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  // 3. If a component is destroyed during a parent component's watcher run,</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  //    its watchers can be skipped.</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  queue.</span><span style="color:#622CBC;--shiki-dark:#DBB7FF">sort</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">((</span><span style="color:#702C00;--shiki-dark:#FFB757">a</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">, </span><span style="color:#702C00;--shiki-dark:#FFB757">b</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">) </span><span style="color:#A0111F;--shiki-dark:#FF9492">=></span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> a.id </span><span style="color:#A0111F;--shiki-dark:#FF9492">-</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> b.id)</span></span>
<span class="line"></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">  ...</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre>
<p>queue를 id 순서로 정렬됩니다. 즉, id 값이 작을 수록 먼저 업데이트 됩니다. <a href="/tech/vuejs/initialize-_init-function/#_init-%ED%95%A8%EC%88%98-%EC%82%B4%ED%8E%B4%EB%B3%B4%EA%B8%B0">4. Initialize - _init 함수</a>에서 살펴보았던 <code>_init</code> 함수를 다시 살펴보면,</p>
<pre class="shiki shiki-themes github-light-high-contrast github-dark-high-contrast" style="background-color:#ffffff;--shiki-dark-bg:#0a0c10;color:#0e1116;--shiki-dark:#f0f3f6" tabindex="0" data-language="js"><code><span class="line"><span style="color:#023B95;--shiki-dark:#91CBFF">Vue</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">.</span><span style="color:#023B95;--shiki-dark:#91CBFF">prototype</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">.</span><span style="color:#622CBC;--shiki-dark:#DBB7FF">_init</span><span style="color:#A0111F;--shiki-dark:#FF9492"> =</span><span style="color:#A0111F;--shiki-dark:#FF9492"> function</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> (</span><span style="color:#702C00;--shiki-dark:#FFB757">options</span><span style="color:#A0111F;--shiki-dark:#FF9492">?:</span><span style="color:#702C00;--shiki-dark:#FFB757"> Object</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">) {</span></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">  ...</span></span>
<span class="line"><span style="color:#66707B;--shiki-dark:#BDC4CC">  // expose real self</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  vm._self </span><span style="color:#A0111F;--shiki-dark:#FF9492">=</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> vm</span></span>
<span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">  initLifecycle</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(vm)</span></span>
<span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">  initEvents</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(vm)</span></span>
<span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">  initRender</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(vm)</span></span>
<span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">  callHook</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(vm, </span><span style="color:#032563;--shiki-dark:#ADDCFF">'beforeCreate'</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">)</span></span>
<span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">  initInjections</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(vm) </span><span style="color:#66707B;--shiki-dark:#BDC4CC">// resolve injections before data/props</span></span>
<span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">  initState</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(vm)</span></span>
<span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">  initProvide</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(vm) </span><span style="color:#66707B;--shiki-dark:#BDC4CC">// resolve provide after data/props</span></span>
<span class="line"><span style="color:#622CBC;--shiki-dark:#DBB7FF">  callHook</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(vm, </span><span style="color:#032563;--shiki-dark:#ADDCFF">'created'</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">)</span></span>
<span class="line"></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">  ...</span></span>
<span class="line"></span>
<span class="line"><span style="color:#A0111F;--shiki-dark:#FF9492">  if</span><span style="color:#0E1116;--shiki-dark:#F0F3F6"> (vm.$options.el) {</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">    vm.</span><span style="color:#622CBC;--shiki-dark:#DBB7FF">$mount</span><span style="color:#0E1116;--shiki-dark:#F0F3F6">(vm.$options.el)</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">  }</span></span>
<span class="line"><span style="color:#0E1116;--shiki-dark:#F0F3F6">}</span></span></code></pre>
<p><code>vm.$mount(vm.$options.el)</code>가 가장 마지막에 호출되는 것을 볼 수 있습니다. <code>$mount</code> 함수는 <code>mountComponent</code>(<a href="/tech/vuejs/initialize-mixin-layer/#lifecyclemixin-%ED%95%A8%EC%88%98">3. Initialize - Mixin Layer</a>에서 이야기 했습니다.)를 호출하는데 <code>mountComponent</code> 함수는 <code>Watcher</code> 인스턴스를 생성합니다. 가장 마지막에 호출되기 때문에 가장 큰 id를 할당 받아 가장 마지막에 view가 업데이트 되게 됩니다.</p>
<h2 id="요약">요약<a class="anchor after" aria-hidden="true" tabindex="-1" href="#요약"><span class="anchor-icon">#</span></a></h2>
<p>이번 포스트에서는 Watcher가 업데이트하는 lazy, sync, queue 3가지 방법에 대해 이야기 했습니다. 기본값은 queue 모드입니다.</p>
<ul>
<li>lazy 모드는 값이 실제로 필요할 때까지 Watcher의 평가를 미루는 모드입니다.</li>
<li>sync 모드는 바로 Watcher가 평가하게 되는 모드입니다.</li>
<li>queue 모드는 한 tick 동안 Watcher가 평가해야 하는 목록을 queue에 저장하였다가 다음 tick에서 평가를 하는 모드입니다.</li>
</ul>
<p>view를 업데이트 할 때도, watcher를 재사용합니다. 모든 값이 업데이트 되고 가장 마지막에 view가 업데이트 되는데 그 이유는 <code>_init</code> 함수에서 <code>$mount</code> 함수가 가장 마지막에 호출되었기 때문입니다.</p>
